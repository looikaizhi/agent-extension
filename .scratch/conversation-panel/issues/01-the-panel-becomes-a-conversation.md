# 01 — 侧栏变成一段对话，宿主拥有它

**What to build:**

把侧栏从「一屏状态 + 几张卡片」改成一段**对话**：用户说的话、agent 指的每一步、它的回答与提问、它为什么这么做（可下拉展开的思考过程），按时间排在一条流里。同时把侧栏与 agent 之间的接口重新设计成**宿主拥有、侧栏拉取**,让今天那批「侧栏错过一条广播就永远卡住」的缺陷在结构上不再可能。

> **2026-09-20 由用户提出**,走 ask-matt 的主干流程(想法 → 票 → 实现)。八项决定由用户定,逐条记在下面。上下文与长短记忆**不在本票**,之后单独谈。

**Blocked by:** 无(guide-stability 全部完成)

**Status:** done — 2026-09-20

## 为什么是现在

真机上遇到侧栏停在「正在想…」怎么也回不来。查下去不是一个 bug,是一类:**侧栏的界面状态是由一条一条广播喂出来的,错过就没了**,而广播的收件人规则还不一致(有的按标签页过滤过头,有的完全不过滤)。已查明的十一条缺陷里,有六条都长在这一条接缝上。对话化本身要求侧栏能回看历史——历史必须有人**拥有**,这正好是那六条缺陷的解药,所以两件事一起做,而不是先打补丁再重写一遍。

## 决定(用户定的)

1. **一条对话按标签页,跨引导存活**——一趟结束后消息还在,可以接着说下一件事;标签页关了就没了(`storage.session`)。
2. **思考过程 = 工具轮次 + 理由 + 用量**——每一轮:调了哪个工具、拿回了什么、模型给的理由、花了多少 token。线程里已经有(`turn.rounds`),不新增采集。原始请求/响应仍留在 trace 开关后面,不进对话。
3. **当前这一步:对话里留一条 + 顶部钉住**——用户要照着做,它不能被后续消息冲走;钉住那块带「跳到目标 / 跳过 / 结束」。
4. **回答流式显示**——侧栏本来就是真正发请求的那一方,文字边生成边往对话里滴。未完成的文字是侧栏本地的草稿,**永不是权威数据**;落定以宿主写下的为准。
5. **其余面板收进抽屉**——主界面只有对话、钉住的步骤、输入框;元素表、抽取本页、检视元素、成本、模型配置收进可展开的工具区,一个功能都不少。
6. **浮层照旧说话**——问题、回答、跨站确认、收场说明仍然在页面浮层上说一遍(10c 的理由不变:用户可能关着侧栏)。对话是权威记录,浮层是当场提醒。
7. **顺手把已查明的缺陷结构性修掉**(见下「缺陷」一节)。
8. **引导进行中用户又说话 = 交给正在走的引导**(08b 语义不变),在对话里它就是一条普通的用户消息。

## 形状

### 领域词

- **Conversation(对话)**:一个标签页里发生过的事,按时间排。`conv:tab-<id>`,`storage.session`,随标签页消失。宿主是唯一的写者。
- **Entry(条目)**:对话里的一条。`said`(用户说的)、`step`(指出的一步)、`answer`(回答)、`ask`(反问)、`note`(宿主说的话:失败、收场、要打开侧栏……)。
- **Round(一轮思考)**:一次模型调用及其工具执行——`tool`、`why`、`result` 摘要、`usage`。挂在**它促成的那条 Entry** 上(`entry.rounds`),这正是下拉展开要显示的东西。
- **Pending(此刻在做什么)**:`idle` / `thinking` / `running_tool` / `waiting_for_panel` / `waiting_for_user`。**由线程算出来,不是侧栏自己记的标志位**——这是「正在想」再也卡不住的原因。

### 接口

侧栏 → 宿主:

- `SAID { tabId, text }`——用户说了一句话。替代今天的 `START_GUIDE`(新一趟、或交给在走的那趟,由宿主判,08b 的逻辑不变)。
- `GET_CONVERSATION { tabId }` → `{ conversation, pending, step }`——**权威读**。挂载时、切标签页时、收到变更提醒时、任何用户动作之后都拉一次。
- 保留:`END_GUIDE`、`CROSS_SITE_DECISION`、`PANEL_INSPECT`、`POINT_AT`(检视器选中后的「指给我」,固定计划)、`EFFECT_CLAIM` / `EFFECT_RESULT`(效果协议不动)。

宿主 → 侧栏:

- `CONVERSATION_CHANGED { tabId, rev }`——只是一句「有变化了」,**不带数据、不权威**。丢了也没关系:下一次拉取就补上。
- 保留 `EFFECT_REQUEST` / `EFFECT_ABORT`。
- **删掉** `GUIDE_STATE` / `GUIDE_ASK` / `GUIDE_EXPLAIN` / `GUIDE_CROSS_SITE` / `AGENT_ANSWER` 这五种广播(不保留兼容路径)。

### 缺陷(本票一并修掉)

结构性消失的:

- **静默拒绝**:注入不进去的页面、没配模型、页面读不到——每一条都成为对话里的一条 `note`,不再只是一个被丢掉的 `false`。
- **切标签页卡住**:侧栏按标签页拉取,切回来就是那条对话的现状;错过任何提醒都不影响。
- **取消不复位**:`pending` 由线程算,结束之后下一次拉取就是 `idle`。
- **广播收件人不一致**:`AGENT_ANSWER` 那种不带 tabId 的全局广播没有了,每条 Entry 都属于某一个标签页的对话。
- **顺序颠倒**:提醒是幂等的,权威数据靠拉,先后到达不再影响显示。

要另外加兜底的:

- **侧栏执行效果时抛异常** → `startEffectListener` 里补 `catch`:无论如何都回一条 `EFFECT_RESULT`(`ok:false`),不让宿主空等。
- **宿主自己执行的工具断在半路**(`observe` / `wait_for`) → `turn.pending` 也要有 deadline,并和在途调用同一套清扫。
- **读数不触发清扫** → `readingArrived` 开头加一次 `sweepExpiredGuideEffect`。

## 进度记录（2026-09-20）

**领域词与接口**

- `Conversation` 进了词汇表（CONTEXT.md），连同「为什么不再用广播喂界面」的注记。`src/agent/conversation/entries.ts` 是纯函数：把线程里的一轮读成可显示的一行（`roundOf`）、往对话上追加（`append`）、把一步的结局盖到显示它的那一条上（`stampStep`），以及**从线程算出此刻在做什么**（`pendingOf`）。19 条单测。
- 宿主侧 `src/host/conversation-store.ts`：`conv:tab-<id>`、`storage.session`、每个标签页一条串行写链。（先放在 `src/entrypoints/` 下，WXT 会把那里的每个文件当入口 —— 构建直接报错，所以挪到了 `src/host/`。）
- 线上协议：`SAID` / `POINT_AT` / `GET_CONVERSATION` / `SKIP_STEP` 进，`GUIDE_STATE` / `GUIDE_ASK` / `GUIDE_EXPLAIN` / `GUIDE_CROSS_SITE` / `AGENT_ANSWER` 五种广播删干净（源码树零残留，剩下的只有解释历史的注释）。提醒只剩一条 `CONVERSATION_CHANGED`，不带数据。
- **提醒必须覆盖状态变化**：调用派出、一趟结束时对话本身没有变化，但「在做什么」变了。漏掉这一点时流式那条一直不亮——`dispatchEffect` 与 `settleEnding` 各补一次 `pingTab`。

**界面**

- `App.tsx` 重写成：头 → 钉住的这一步 → 会滚的对话 → 输入框 → 工具抽屉。`Conversation.tsx` 画条目与可下拉的思考过程；`Tools.tsx` 收纳抽取、元素表、检视（含「指给我」）、成本、模型配置。
- 路标与三轴原本要随旧广播一起消失——那是产品的透明度承诺，补回来了：写在**产生它的那一步**的条目上（`entry.route` / `entry.axes`），看完之后还能回头看。
- 流式：侧栏本来就是发请求的那一方，在 `startEffectListener` 里把流**分一路**出来（不动运行循环），`draftTextOf` 从还没写完的 JSON 参数里取出已经写出来的那一截（7 条单测，含半个转义不猜下一个字）。草稿是侧栏本地的，落定以宿主写下的为准。
- 两处渲染 bug 在截图里抓到并修掉：输入框用 sticky 浮在对话中间挡住消息；钉住那张卡片里的 Markdown 原样显示。

**缺陷（结构性消失的）**

- 静默拒绝 → 三条拒绝路径都成了对话里的一条 `note`（注入不进去的页面、没配模型、页面读不到）。
- 切标签页卡住 → 侧栏按标签页拉取；并且收到别的标签页的提醒时会复核自己在看哪一页（这一条同时修了「错过一次 onActivated 就一直显示错的那条对话」）。
- 取消不复位 → `pending` 每次从线程算，结束后下一次拉取就是就绪。
- 广播收件人不一致 → 不带 tabId 的全局广播没有了。
- 顺序颠倒 → 提醒幂等，权威数据靠拉。

**缺陷（加了兜底的）**

- 侧栏执行效果时抛异常 → `startEffectListener` 里 catch，无论如何回一条 `EFFECT_RESULT(ok:false)`；用假的 `chrome` 驱动监听器的 2 条单测证明它。顺带把成功/失败两条路收到一个出口，守卫「只在两处 sendMessage」照旧成立。
- 宿主自己执行的工具断在半路 → `tool:<threadId>` 记下期限（`HOST_TOOL_TIMEOUT_MS = 45s`），清扫时交回「这一页读不到」/「没等完」。3 条单测。**只管宿主自己跑的那种**：`read_doc` 走效果协议、有自己的期限，第一版没分清，把 `read-doc.spec` 的「没读到」变成了「读不到」——单测当场红，已改。
- 读数不触发清扫 → `readingArrived` 开头补一次。

**验证**

- 类型检查 0；单测 988 全绿（新增 31 条：对话 19、流式 7、侧栏兜底 2、宿主工具期限 3）；e2e 259/259（新增 11 条，见下）。
- e2e 新增一段「对话」：调用在途时的「在想」是算出来的、中途切标签页再切回来状态正确、结束后回到就绪、思考过程带工具与理由与用量、侧栏把它画成可下拉的块、内容脚本用不了的页面上说一句话、回答边生成边显示、落定以宿主为准。为了真的验流式，夹具服务器加了一个**一段一段发**的模型端点（`res.flushHeaders()`，否则第一片被缓冲）。
- 排查中踩到的两个测试坑，记下来免得再犯：对话是**累积**的，断言必须等「这一条」而不是读「最新一条」；`locator.innerText()` 在元素不存在时会等满 30 秒默认超时，轮询要用 `page.evaluate` 直接读。
- 评估 harness（`evals/task/live-github-run.mjs`）随之改：`SAID` 起引导，异常与「思考」都从对话读，并打印这一步用过的工具链。

**真机冒烟（2026-09-20，用户同意用 `.env.local` 的 key 真跑）**
