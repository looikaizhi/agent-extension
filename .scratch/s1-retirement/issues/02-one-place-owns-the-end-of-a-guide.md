# 02 — 一趟引导结束，只有一个地方说了算

**What to build:** 宿主里出现一个终结流程，接管「一趟引导结束」要做的四件事：中止在途 Effect、落盘 Run record、删 Thread、通知外部世界。这一票只把「用户显式点结束引导」这一条路改为走它——**行为零变化**，那条既有的端到端断言就是这次改动的网。

它必须从一开始就是并发安全的，因为 MV3 的多个监听器会并发跑。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 宿主引导 Effect 的依赖对象增加一个 Run record 存储端口，使终结流程可以在单元测试里被驱动
- [x] 终结流程按固定顺序执行：中止在途 Effect → 落盘 Run record → 删 Thread → 交回给调用方去做平台调用（清浮层、广播）。**它自己不碰任何平台 API**
- [x] 顺序有测试：Run record 必须在删 Thread 之前写。承接它的测试文件的既有夹具已经在记录存储调用顺序，直接用
- [x] **幂等**：对同一个 Thread 重复调用是无操作——不重复写 Run record、不重复要求广播。有测试
- [x] **不可复活**：终结之后迟到的 Effect 结果被识别为「针对一条已结束的 Thread」并丢弃，不得把记录写回来。有测试
- [x] **Run record 写失败不阻断终结**：仍然删 Thread、仍然中止 Effect，并把失败明确交回调用方去告知用户。有测试
- [x] 现有的按键串行队列扩展到覆盖所有状态写入，而不只是重规划那一条路径。**复用它，不新造机制**
- [x] 「用户显式点结束引导」改为调用这个流程，行为与今天逐字一致；既有的那条端到端断言保持绿
- [x] `npm run verify` 全绿
