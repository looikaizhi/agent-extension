# 05 — 归约器学会「固定计划」，而它永不调用模型

**What to build:** 归约器接受一种新的计划来源：调用方交来一串已经写好的引导步骤，归约器直接落成步骤与游标并把第一步画出来，**不抽取、不规划、不调用模型**。计划走完就结束。

**这一票只做归约器和它的测试，不切换任何生产入口。** 检视器的接线在 06 那次原子切换里完成——先切一半会让一条既有的端到端断言变红。

**Blocked by:** 01

**Status:** done

- [x] 归约器新增一种开始形态，带 `goal`、当前元素表与那串步骤。**没有 Effect id**——它不需要 Effect 预算，这一点本身就是它与模型驱动那条路的分界
- [x] Thread 记录这趟计划的来源（固定 / 模型）
- [x] 固定计划落成之后：产出呈现第一步的效果，**不产出模型调用**，配额计数不变
- [x] 固定计划耗尽时走 03 那条统一终结流程，**不发起模型调用**
- [x] **关键验收**：固定计划在**等待窗口关闭之后**（用户盯着不动、页面没有变化）依然是零模型调用。归约器今天在这种情况下会重新规划一次——那条路径是为模型驱动的引导加的，对固定计划必须关闭。**没有这条测试就不算完成**
- [x] 步骤携带的是跨快照的持久身份描述，不是此刻的绑定结果；绑定发生在渲染器要画它的那一刻
