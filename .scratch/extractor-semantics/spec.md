# 规格：抽取器的语义补全，与两条安全收口

**一张票，四段改动，顺序是硬的。**

起因：真机上引导指错位置，怀疑是模型看到的页面信息太少。这一票把「补语义」和「补的过程中会捅出来的两个安全口子」一起做完，
并且把顺序钉死——**`redact` 必须在「邻近文字」之前落地**，否则等于主动把页面上显示的 API key 送去端点。

| 段 | 做什么 | 代价 | 风险 |
|---|---|---|---|
| **0** | 两条安全收口 | 0 token | 无（纯收紧） |
| **1** | 免费的语义：地标 role 名、属性只发真值 | ≈ 0 | 低 |
| **2** | 定向补 href 末两段（只给名字失效的 11%） | +5.5% | 低 |
| **3** | 邻近文字 | 待定，上限 +46% | **高，见「说清楚的那一件事」** |

## 段 0 — 两条安全收口（先做，独立于其余三段）

### 0-A `structuralRedFlags` 接进指路路径

今天 [`link-safety.ts`](../../src/core/security/link-safety.ts) 里的 V-1…V-4 写好了、测过了，
但只在 [`read-doc.ts:107`](../../src/agent/tools/read-doc.ts) 被调用。
[`point.ts:363-369`](../../src/agent/agents/guide/output/point.ts) 的跨站分支**只调了 `sameHost`**：

```ts
const target = state.table.items.find((i) => i.ref === shown.ref)?.href;
if (target && !sameHost(state.table.url, target)) {
  const to = hostOf(target);
  if (to) return { ...pendingCrossSite: to, effects: [requestCrossSiteConfirm({ from, to })] };
}
```

后果：一个指向 `https://аpple.com/...`（西里尔 `а`）的链接，跨站卡上写的就是 `аpple.com`，
**和真域名在屏幕上完全一样**，用户分辨不出。而 V-1 homograph 正是为这个场景写的。

**改：** 拿到 `target` 之后先跑一次 `structuralRedFlags(new URL(target))`，命中就**拒绝这一步**（不是弹卡），
并把红旗名写进给用户的那句话。

> **为什么是拒绝而不是把红旗写进卡片让用户决定。** 这四条都是**结构性**判据，不涉及「这家是不是好人」的判断
> （那是 P-1，仍然搁置）。一个带 userinfo 的地址、一个非 ASCII 域名、一个 `data:` 链接、一个指向内网的链接——
> 没有任何一种是正常引导会需要的。让用户在一个他分辨不出真伪的域名上做决定，等于把风险转嫁给他。
>
> **为什么不是给模型看 href 让它判断。** 那是把确定性问题交给概率装置。判据已经是纯函数、已经有测试，
> 直接跑一次比让模型看一眼可靠得多，而且**零 token**。

### 落地记录（2026-10-01）

**做成了 `point.violation` 的一条规则**，不是 `consequence` 里的分支——`violation` 正是为「这个信封不能要」准备的钩子，
而且模型会收到理由、可以改指别处，不必赔掉整轮。

**范围从 V-1…V-4 收窄成 V-1 / V-2 两条**，而且是 e2e 逼出来的：接上四条之后 272 里红了 5 条，
根因是**整套 e2e 夹具服务在 `127.0.0.1` 上，被 `private_network` 全拒了**。

> 这不是测试环境的怪癖。**用户在自己 `localhost:3000` 的应用上被引导是正常场景**，那一页上每个链接都是「内网」。
> `private_network` 属于 `fetchDoc`——那里担心的是*我们*去够用户的内网，而指路时用户本来就站在那儿。
> `scheme` 一并去掉：`mailto:` 链接到处都是，指着它说「点这里给支持发邮件」是正当的一步。
>
> 留下的两条共同点是**伪装**：地址在屏幕上看着像一个地方、实际去另一个地方。
> 跨站确认卡恰好挡不住这一类，因为它能展示的就是那个看着没问题的主机名。**这才是这条规则真正的靶子。**

测试：`validate.spec.ts` 新增 9 条（四种伪装形态各一，加同站/跨站/不可解析/无 href 四条放行，
再加两条明写「有意不管」的 `mailto:` 与 `127.0.0.1`）。

### 0-B 值级别 `redact`，并用守卫钉死

[`sensitive.ts`](../../src/core/security/sensitive.ts) 开头有一道闸门：

```ts
const entry = el.localName === 'input' || el.localName === 'textarea' ||
              role === 'textbox' || role === 'searchbox' || role === 'spinbutton' ||
              el.isContentEditable === true;
if (!entry) return false;   // ← 不是输入框，一律不算敏感
```

它回答的是**「这个元素是不是一个填密码的地方」**，必须看活的 DOM 节点，这个设计是对的、不要动。
缺的是另一个问题：**「这段字符串本身像不像一个密钥」**。

今天已经存在的口子：`<button aria-label="复制 sk-live-abc123...">` 的可访问名就是那串东西，
原样进表、原样发给端点。名字只做 `NAME_MAX_LEN = 120` 截断，**不做任何脱敏**。

**改：** 新增一个纯字符串函数，凡是要进 `toPromptText` 的字符串都过它：

```ts
// src/core/security/redact.ts —— 零 import，纯函数，能在单元层全覆盖
const SECRET_SHAPES = [
  /\b(sk|pk|rk)-[A-Za-z0-9_-]{16,}/,        // OpenAI / Stripe 一类
  /\bgh[pousr]_[A-Za-z0-9]{20,}/,           // GitHub token
  /\bAKIA[0-9A-Z]{16}\b/,                   // AWS access key id
  /\bLTAI[A-Za-z0-9]{12,}/,                 // 阿里云 AccessKey
  /\beyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\./,  // JWT 三段式
  /-----BEGIN [A-Z ]*PRIVATE KEY-----/,     // PEM
  /\b[0-9a-f]{32,}\b/,                      // 长 hex
];
export const REDACTED = '（这里有一串像密钥的内容，已隐去）';
export function redact(s: string): string { … }
```

**新增一条架构守卫：** `toPromptText` 写进输出的每一处字符串都必须经过 `redact`
（判据形态参照现有的「注进页面框架里的那段探针只许看尺寸」——扫 AST，加合成违例自检）。

> **为什么是替换而不是删除。** 模型需要知道「这里有个东西」才不会去猜，和 `omitted` 计数「说出来」是同一个道理。
> 一个悄悄消失的名字会让模型以为那个控件不存在。
>
> **为什么是值级别而不是扩大 `isSensitive`。** 两者判的不是一回事，而且 `isSensitive` 的 `entry` 闸门有它的理由
> （`input[type=password]` 没有 ARIA role，靠结构判而不是靠 role 判）。硬把它扩大到所有元素会引入大量误报。
> 值级别判据是纯字符串，**能进单元层，不需要 DOM**，这是它能被测透的原因。
>
### 落地记录（2026-10-01）

**模式集是量出来的，不是想出来的。** 初稿里有一条 `/\b[0-9a-f]{32,}\b/`（长十六进制），
拿 22 个夹具的 **1005 条真实字符串**（名字 + 组标题 + 页面标题 + URL）体检时发现它会吃掉
**完整的 commit SHA**——GitHub 每一页都是。去掉之后：**误报 0/1005**，八种真形态全中。

> **为什么不按熵下手。** 「这段字符看起来很随机」在真实页面上试不通：commit SHA、构建号、资源 id、
> CSS 类名哈希到处都是，而它们正是模型用来分辨「哪一行是哪一行」的东西——去重那条规格花了大力气才把这类区分留住。
> **宁可漏掉没有前缀的自定义密钥**（用户不会把密钥贴在导航栏上），也不能把 SHA 当密钥吞掉（那会直接让引导指不准）。

**接入点五处**：`pageLabel(url)`、`title`、组标题、条目名、框架标题与 host。URL 也过——`?token=…` 的页面不罕见。

**守卫是绊线，行为测试才是门。** 架构守卫只能在文件级问「import 了并且真的调用了」，
挡的是「连 import 一起删掉」。真正的门是 `redact.spec.ts` 里「接入点」那一组：
把密钥塞进上面五个位置，断言发出去的文本一条都没有——**它不关心内部怎么写，所以重构挪动调用点不会让它误绿。**

> **为什么必须排在段 3 之前。** 段 3 把页面上显示的文字放进表里，而显示出来的密钥（设置页的 API key、恢复码、
> `<code>` 块里的连接串）恰恰就是紧挨着「复制」按钮的那种文字。顺序反了就是主动泄露。

## 段 1 — 免费的语义

### 1-A 地标 role 名当组名，替代「拿标题文字当组名」

今天 `path` 取的是最近的地标或标题的**文字**。改成 `role + name`：

```
今天：  Repository:
改后：  navigation "Repository":
```

区域语义（`banner` / `navigation` / `main` / `complementary` / `contentinfo` / `search` / `form`）
是模型判断「这一块是干什么的」最便宜的线索，而它现在完全不在表里。每个组标题多几个字符，**全页不到 100 token**。

> **为什么这条值得单独列。** 「About」那一栏在今天的表里就是一行 `About:`，模型看不出它是 `complementary`（补充说明）
> 还是一个可点的区块。`navigation` 和 `complementary` 对「下一步该往哪走」的含义完全不同。

**落地（2026-10-01）：全页只多 29 字符 / 8 token。** repo-home 上真实产出两条：
`navigation "Repository":` 与 `complementary "About":`。

> **实现上分成了两件事，是有意的。** 新增 `PromptItem.landmark` 只参与渲染，**不进 `Descriptor`、不进去重的键**——
> `scope` 仍然只用 `path` 的文字。`bindStep` 的 scope 是子串包含匹配，把 role 混进那根字符串，
> 会给一次跨快照重绑多添一个可能变化的因子，而这条改动想买的只是「这一块是干什么的」这点语义。
>
> **没有名字的地标照旧不进 path。** 给 `<main>` 开一个组会让整页多一级缩进（2 空格 × 300 条），换来的只是一个词。

`project.spec.ts` 有 4 条断言旧格式的测试红了——**这是设计要的效果**（改了模型读到的东西就得有人看一眼），
逐条核对后按新格式更新，其中「分组名里的换行不能伪造出一级缩进」那条的性质更强了：地标那层现在还多一层引号转义。

### 1-B 属性只发真值 —— 核查，不一定要改

核下来结论反了一半：**「只发真值」本来就是对的**（每一条都在判 `=== 'true'`），
但核出了一件更要紧的事——**这些状态在生产里从来没发出去过**。

`resolveState` 里除 `disabled` 外的整组都关在 `profile !== 'interactive'` 后面，
而 `background.ts` 的两处 EXTRACT 都写着 `profile: 'interactive'`。
既没有一条测试、也没有一个夹具用过 `aria-expanded`——两边同时为空，谁都发现不了。

**改：把「能挡掉一次白走的步」的那几条移出闸门**——`expanded`/`collapsed`、`checked`/`mixed`、
`selected`、`current`、`readonly`。`required`/`invalid`/`busy` 留在 `+context`：
它们说的是「这个表单域本身怎么样」，不是「该不该指这一个控件」。

> **`collapsed` 是这组里最值钱的一条。** 实测里有一趟引导把同一个按钮点了五次，
> 而它要的控件就在那个按钮展开的面板里——`collapsed` 正是那句「里面还有东西」。
>
> **代价为 0（在现有语料上）**：22 个夹具 355 条控件里带状态的是 **0 条**，因为这些夹具本来就不用 aria 状态。
> 这同时说明语料覆盖不到这条改动，所以补了 `tests/unit/state.spec.ts` 9 条直接测 `resolveState`
> （单元层没有 DOM，用最小假元素——这个函数只碰 `getAttribute` 和四个属性）。

## 段 2 — 定向补 href 末两段

**只给满足以下任一条的条目补：`nth !== undefined` 或 `nameSource !== undefined`。**
带的是 `new URL(href).pathname` 的**最后两段**，不是完整 URL。

```
e40 link ~"详情" #2 →/instances/i-0abc123
```

代价实测 **+5.5%**（repo-home 上 39 条 / 196 token）。

> **为什么只给这 11%。** 名字本身说得清楚的时候，href 是纯重复。这跟已有的 `~` 标记是同一个思路——
> **只在名字失效的地方花钱**。
>
> **为什么是末两段而不是完整 pathname。** 完整 pathname 是 +44%，末两段 +26%（全量）；
> 而承载信息的几乎总是尾部（`/instances/i-0abc123` 里的资源 id、`/settings/billing` 里的 `billing`）。
>
> **为什么这不违反 S-07。** S-07 说的是**模型的输出**只能是 ref、不能是 URL，那是输出 schema 的约束。
> 让模型**看见**目的地和让它**编造**目的地是两件事。而且 href 其实已经在漏进去了——
> 链接没有可读文字时 `href` 就是名字回退源之一，那一条会带着 `~` 发出去。这一改只是把已经发生的事做得有规矩。
>
> **一条反证，必须写下来。** repo-home 上「同 role 同名但 href 不同」只有 10 组，而且全是文件表里的提交链接；
> `nth` 在 355 条里只触发过 3 次。**所以这一条该做，但别指望它是主要增益。**
> 它真正的受益场景是云控制台那种「20 行每行都有 编辑/删除/详情」的页面，而我们的语料里没有这种页。

**落地（2026-10-01）：+206 token，+6.0%**（预估 +5.5%）。实现是 `toPromptText` 里的 `hrefTail`，
只取 `new URL(href).pathname` 的最后两段，渲染成 `→/master/.github`。

反证那一段现在有了反转：repo-home 上真正吃到好处的**正是那 39 条弱名字的提交链接**——
它们原来是 39 行几乎一样的名字，现在各自带着 `→/master/.devcontainer`、`→/master/.github`……
**也就是说「同名不同链只有 10 组」这个统计低估了收益**，因为真正难分辨的那批名字里带的是提交信息而不是文件名。

`href.spec.ts` 原有的 5 条全部照旧绿——它们的夹具既无 `nth` 也无 `nameSource`，**边界正画在这里**；另补 6 条。

## 段 3 — 邻近文字（风险最高的一段）

**目标不是把整页文字放进来**，是把「控件所在的最小语义容器里的直接文字」放进来，去重后截断。

需要先定义清楚三件事，**定义本身就是这一段的主要工作**：

1. **什么叫「最小语义容器」** —— 候选：最近的具名祖先（有 accessible name 的）、或最近的 `listitem`/`cell`/`group`/`region`。
2. **取哪些文字** —— 只取该容器的**直接**文字子节点，不递归；否则会把整棵子树的文字拼起来，
   那正是 Playwright 在表格上爆掉的原因（同一段字在 `row`/`cell`/`link` 各算一遍）。
3. **怎么去重** —— 和控件自己的 name 相同或互为前缀的，不发。

**上限约束：** 这一段的产出**必须计入 `budgetFor` 的预算**，不能在预算之外追加。

> **为什么不能全量加。** 实测：全页可见文字 ~1,623 token，加进去是 3,561 → 约 5,200（+46%）。
> 但 AgentOccam 那条实测结论是反直觉的——**不加信息、砍冗余反而涨点**，因为噪音本身会拉低选择质量。
> 而我们自己也有一个同向的数：词法相关性打分的 baseline top-1 只有 **60%**，说明「多给字面文本」不等于「选得更对」。
>
> **为什么排在最后。** 它是四段里唯一一个**可能让效果变差**的。前三段都是单调改进（安全收紧、语义增加、定向补充）。

### 落地记录（2026-10-01）—— 做了，但**测量计划被推翻了**

**规则迭代了三版，前两版都是用测量推翻的：**

| 版本 | 规则 | 结果 |
|---|---|---|
| 一 | 祖先的**直接**文字子节点 | 355 条里只命中 **1** 条。真实页面的说明写在 `<span>`/`<p>` 里，是控件的**兄弟**而不是祖先的裸文本 |
| 二 | 加上「自己不含控件的子元素」的文字 | **354/355 条都命中**，而且全是同一段页面级标题，**+2648 token（+70%）纯噪音**——AgentOccam 警告的那个形状，原样复现 |
| 三 | 加一条终止：**这一层里除了它自己还有别的控件就停** | 19/355 = 5.4%，repo-home **+0 字符** |

第三版的道理：一个容器里只要出现第二个控件，它的散文说的就是**这一组**，不是这一个。

命中的地方信号很好，正是消歧那一类：

```
dup-across-sections:  button "Copy" · "Payment methods" / "Webhooks" / "Terminal"
zh-console:           button "删除" · "允许 SSH 入站" / "允许 HTTP 入站"
dup-table-rows:       button "Stop" · "i-aaa111" / "i-bbb222"
```

**但在唯一那张真实页面（repo-home，一份 GitHub 存档）上一条都没命中、一个字都没多。**
密页面上每个控件周围都有别的控件，终止条件立刻触发。
所以这一段的实际形状是：**零成本，偶尔有用**——而不是「解决了信息不足」。

## Out of scope（写下来是为了以后别重新讨论）

- **不换成 YAML / aria 快照。** 理由见上面的实测底账。
- **不发完整 href。** +89%，且承载信息的是尾部。
- **不加 `cursor: pointer` 兜底判定。**（browser-use 的第 13 道）会把大量装饰元素拉进表，与「宁缺毋滥」相反。
- **不上截图 / Set-of-Mark。** 产品定位是「一个端点用到底」，用户可能配纯文本模型。真要做，先给验收加一项「认不认图上的编号」。
- **不动 `Descriptor` / `ref` 的形态。** `ref=eN` 是活句柄，`Descriptor` 要在**用户点完、页面变完之后**找回同一个元素。这是产品需求差别，不是风格差别。
- **不做「指向正文」。** 段 3 让模型**看见**文字，不让它**指向**文字。这是两件事，详见文末附录。
- **不让新增内容跨步累积。** 新增的一切只能进 `toPromptText` 的表体（每步被替换），**不能进 `historyText`**（每步都在长）。
  越过这条线就退回 Playwright MCP 那条「12 步之后躺着 11 份过期页面、一个任务 114k token」的曲线。

### 说清楚的那一件事 —— 段 3 没有门

上面五道门回答的都是**「我改的是不是我想改的」**。
没有任何一道回答**「模型选得更对了吗」**。

唯一能量后者的是 `evals/decision`（语料回放 + `gate.ts` 的配对差 95% 区间），
而 **2026-09-25 定过「不再跑测评」**。所以：

- **段 0、1、2 不受影响**：它们是安全收紧、语义增加、定向补充，方向单调，靠上面五道门足够。
- **段 3 受影响**：它有可能让效果变差，而**当前没有任何东西会发现**。

**这是一个需要你拍板的岔路，我不替你选。** 三条路：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A** | 只为段 3 跑一次 decision eval 做前后对照，跑完照旧不跑 | 一次真调用的钱，但有了确定的答复 |
| **B** | 做段 3，但放在一个开关后面（`flags.ts` 已有 flag 机制），真机觉得不对就关掉 | 零测量成本，靠人眼；开关要记得清理 |
| **C** | 这一票只做 0/1/2，段 3 单独开票，等有尺子再说 | 最稳，但「信息不足」这个原始假设仍然没被验证 |

> **推荐 A。** 段 3 是这一票里唯一有下行风险的改动，也是原始假设（「信息太少」）的直接检验。
> 花一次钱换一个确定的答复，比做完之后长期不知道它是帮忙还是添乱划算。
> 而且还有一条反向证据值得在拍板前看一眼：**`observe` 工具至今被选中 0 次**——
> 我们已经给了模型一条「我想再看一眼这一页」的路，它一次都没用过。
> 这说明「模型缺信息」和「模型不会为缺信息做任何事」是两个不同的诊断，目前只有后者有证据。
> 如果是后者，段 3 的收益会远低于预期，真正该改的是**提示词里怎么描述这些工具**。

## 附：终局也要框（这一票不做，但形状已经理清）

**需求（2026-10-01 澄清）：** 不是「旅程中途多一种『读一读』的步骤」，而是**最后一步本身要指向目标**。
「帮我找到这条新闻」——走完之后要把那条新闻框出来，用户才知道到了、知道要看的是哪一段。
**终点也是一次指向，只不过指的是内容而不是控件。**

> 我第一版把它理解成一种新的中途步骤，于是推导出「步骤生命周期要改」「需要新的完成事件」等等。
> 那是过度设计。按终局这个框架，那些问题大部分自己消失。下面是修正后的版本。

### 一条直接支持它的证据

[`done.ts:15`](../../src/agent/agents/guide/output/done.ts) 的 `DONE_EVIDENCE` 里已经有一项：

```ts
export const DONE_EVIDENCE = ['content_on_page', 'page_address', 'step_completed'] as const;
```

**模型已经被要求说「我在这一页上看到了那个内容」，但它没有任何办法把那个内容指出来。**
词汇表已经预见了这个情形，机制没有跟上。

同一个文件 22 行写着当初的假设：

> *「a step always names a control, and completion names none. No `ref` and no control name:
> there is nothing to point at, which is the whole content of the message.」*

**这个假设对「做成一件事」类目标成立，对「找到一样东西」类目标不成立。** 后者的完成恰恰就是「它在这里」。

### 四个问题，按终局框架重答

| # | 我原来的担心 | 按终局框架的答案 |
|---|---|---|
| 1 | 内容节点会和控件抢 `maxNodes` 预算 | **基本消失。** 内容抽取只在终局需要，可以是按需的第二次抽取，甚至限定在模型点名的那个区域内。常驻表不变。 |
| 2 | 段落没有 accessible name，`Descriptor` 重绑不了 | **大幅简化。** 终局框不需要跨导航、跨重规划存活——画一次，运行就结束。它只需要在滚动/重绘时重绑，那是**同一快照内**的事，`tracker.ts` 已经在做。 |
| 3 | `observe` 步没有完成事件，会卡住 | **完全消失。** 这是我最大的误读。终局框不需要完成事件，**因为运行到此结束**——`model_done` 就是它的终点。 |
| 4 | 产品定义要改 | **缩成一句话的事。** 不是新增一种模式，是把现有定义走完：「指出你该点哪里，**直到指出你要的东西在这里**」。 |

### 而且它让 `Arrival` 变强

今天的到达判定是「终点 URL + 停下时高亮的那一步」，而 `done` 结束时屏幕上什么都没有
（`lastStep.kind === 'none'`）。如果 `done` 必须指向目标，那：

- 150 趟里「终点对但最后一步不对」的 17 趟、以及「到了又走开」的 12 趟，**有一部分会变成可判的**
- 模型要说「到了」就得**指出证据**，这比写一句 `why` 强得多——和 `previous_step`、`DONE_EVIDENCE`
  用封闭列表逼它分类是同一个思路

### 真正剩下的工作只有两件

1. **内容节点要有 ref。** 两处放行：[`extract.ts:88`](../../src/core/extractor/extract.ts) 的
   `continue`（今天只放 interactive / landmark / heading）、
   [`project.ts:78`](../../src/core/extractor/project.ts) 的 `targets` 过滤
   （今天只放 `PRIMARY_INTERACTIVE_ROLES` 或 `focusable`，**连已提取的 heading 都进不了 items**）。
   按需触发，不进常驻表。
2. **终局输出携带高亮目标。**
   [`explain`](../../src/agent/agents/guide/output/explain.ts) **已经是这个形状了**——
   它带 `refs`，schema 里明写「它们会被逐个框出来给用户看」，上限 `EXPLAIN_MAX_REFS = 5`。
   所以要做的是给 `done` 加一个同样的口子，而不是发明新机制。

渲染层不用动：`UserAction` 里已经有 `'observe'`，[`outline.ts:31`](../../src/shared/outline.ts) 正用着它。

> **为什么仍然不塞进这一票。** 它要改 `done` 的信封形状（契约层）、要新增一条按需抽取的路径，
> 还要动 `Arrival` 的判定——本票四段都只动抽取器与投影，混进来就失去「独立可回滚」这个性质。
> **但它现在是一张形状清楚、可以直接写的票**，不再是一个开放问题。
