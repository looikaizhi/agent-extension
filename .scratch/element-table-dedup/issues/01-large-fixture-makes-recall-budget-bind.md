## 收尾时发现、要交给 02 的两件事

**一、`~` 兜底名标记在整份语料里覆盖率为零，去重判据不能指望它。**
规格里的判据一写的是「兜底名（`~` 标记，来自 title/href/testid）的名字重复了同页某条真名的开头 → 删兜底名那条」。实测：`computeAccessibleName` 自己就把 `title` 当兜底返回，于是 `classifySource` 把它归成 `content`，`nameSource` 不被记录——**整份语料 189 条一条都没有**。判据二（只裹着一个可交互子节点且自身不可点的包装）也不适用，因为那条行链接自己就可点。

所以 02 的去重判据必须改成可观测的事实：**「名字完整包含同一行另一条的名字，且 path、role 相同」**。fixture 里那四条 Ref 的形状是对的，能删的东西在，只是不能靠标记去认。

`~` 标记对 title 来源静默失效，是产品侧一个独立问题——它存在的理由正是告诉模型「屏幕上根本没画出这几个字」。本票不改产品代码，未处理。**值得单开一张票。**

**二、`captured/` 里 21 份既有产物被顺带全量重写。**
`capture.mjs` 无条件 `fs.rmSync(OUT)`，任何一次抓取都会重写全部产物。本票不改表的形状，所以这 21 份的差异只有 `snapshotId` 与耗时噪声。02 的验收项「21 个既有语料全部重新捕获，每一份的变化都看过」仍然要做，但要知道这批 diff 里已经混进了本票产生的噪声。

**三、loader 换了位置。** 取产品预算需要一个能解析 `@/` 与无扩展名导入的 loader。原来那个在 `tests/spike/` 下，且把 `src/` 写死成一个绝对路径——让 `npm run eval` 只在一台机器上可跑。已移到 `tests/alias-loader.mjs`，`ROOT` 由 `import.meta.url` 推出，五处 spike 脚本的用法注释一并指向新位置。
