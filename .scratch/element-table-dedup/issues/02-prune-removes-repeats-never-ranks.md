# 02 — 裁剪换判据：去重 + 导航地标保底 + 尾部切片

**What to build:** 用户停在页面中段问「这个仓库的 CI 怎么配置」，扩展指得出屏幕上方的 `Actions`——不再因为它离视口远就把它丢掉。01 那张报红的 fixture 变绿。

裁剪不再回答「这 350 个元素里哪 150 个更重要」。那个问题我们没有能力答对：项目里那套会读用户目标的词法打分实测在七个目标里丢掉五个正确入口，因为用户说中文而页面写英文（「CI 是怎么配置的」对应的入口叫 `Actions`，三元字符 Jaccard 恒为 0），而且它会把一条字面含 `ci` 的提交信息留下来。一手来源里唯一按目标相关性剪枝的框架用的是专门训练的 cross-encoder，不是打分规则。

改成回答另一个问题——「这两条是不是同一件事说了两遍」。这个问题有确定答案，靠比对名字就能答，不需要理解目标、不需要猜语言。

固定三步，顺序不可换：

1. **删 `Restatement`**（无损）——**判据在 01 号票收尾时改过，别照规格初稿写**：初稿说「兜底名（`~` 标记）重复了真名」，但实测 `computeAccessibleName` 自己就把 `title` 当兜底返回，`classifySource` 于是归成 `content`，**整份语料 189 条一条 `nameSource` 都没有**，`~` 标记认不出东西来。改用可观测事实：**名字完整包含同一行另一条的名字，且 `path` 与 `role` 相同**。删完不丢任何一个可点目标。真机实测这类复述约占 32%，且正集中在把导航挤掉的那一块。
2. **导航类地标保底**——这些元素永不被裁，无论页面多大。**注意不能用整个地标集合**：里面有 `main`，按它保底等于把整个文件列表一起保底，裁剪就白做了。只取导航性质的那些。
3. **尾部切片**——仍然超预算才按文档顺序切掉末尾。丢弃位置从此固定在页面靠后，不再随用户滚到哪里漂移。

**预算同时提到 400，不能拖到后面那张票。** 七个目标里 `Documentation` 在正文里、不在任何导航地标下，光靠保底救不回来；不提预算，这张票做完 recall 还是红的，中间状态就是坏的。

视口彻底退出裁剪决定，打分函数和视口带参数一并删除。这也让高亮时的滚动不再形成正反馈——文档顺序与滚动位置无关，所以高亮模块一行都不用改。

## 做完之后必须记下的三件事

**一、recall 的修复完全来自预算，去重和保底一条都没生效。**
`repo-home` 去重后是 316 条（= 307 个 `<a>` + 9 个 `<button>`，**去重删了 0 条**），而新预算是 400，所以它根本不再截断——尾部切片和入口保底在这张语料上都没有机会执行。两者目前**只有单元测试覆盖**。

**二、这把尺子已经量不到它当初要量的东西了。**
`repo-home` 一旦不截断，它就不再能发现「保底坏了」这类回归。要继续守住保底和尾部切片，需要一张候选数超过 400 的语料。**建议单开一张票**，而不是把这张改大——这张现在证明的是「一个真实的仓库页装得下」，那也是有价值的事实。

**三、我在这张票上被 code review 抓到一处错误推理。**
我曾断言「保底按地标走、地标又决定 `path`，所以一个 `nth` 分组只能整组保底或整组不保底，切不出跳过前面留下后面的子集」，并据此把 F-5 那条测试弱化成「幸存者带 `nth: 1` 而非 `undefined`」。**漏了无名地标**：`pathOf` 只在地标有名字时才把名字写进 `path`，所以一个无名 `<nav>` 给出保底资格却不改变分组键。评审给出的反例已经取代我那条弱化版，而且比旧版更好——确定性，与滚动无关。

**四、ADR 0012 里的「32%」已按实测更正。**
那个数是按「名字包含」量的，而那个口径会删掉 href 不同的兄弟链接——丢目标。ADR 已加一节记下这件事，并把成本表从估算的 234 条 / +41% 改成实测的 316 条 / 约 +70%。
