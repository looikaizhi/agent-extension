# 03 — 被切时说清楚缺的是哪一部分

**What to build:** 表真的装不下时，模型知道**缺的是页面靠后的部分**、缺了多少，而不只是知道「不全」。

现在只有一句「这一页还有更多元素没有列出」——它说了「不全」，没说「哪里不全」。02 之后丢弃位置是确定的（按文档顺序切末尾），这个信息我们第一次有能力给出来。

一手来源里 browser-use 的 `[End of page]` 之所以有用，是因为它给的是**位置锚点**而不是一个布尔。表尾是模型读完整张表之后看到的最后一样东西，紧挨着它要做决定的地方，所以那一行放在表尾。

**不要照抄 browser-use 那三处「你看到的只有视口内的元素」**——那描述的是我们在 02 之后不再具备的限制，对我们是假话。

## 做完之后

`PromptTable.truncated: boolean` 换成了 **`omitted: number`**，而不是两个字段并存。带数字这件事必须有个来源，而 `truncated === omitted > 0` 是同一个事实的两份记录——这一整批改动都在消灭这种东西。改动面比想象的小：生产代码里只有 `StatsBar.tsx` 一处读它（顺带把徽标从「已按预算裁剪」改成「已按预算裁剪 N 项」），其余全是测试字面量。

注意 `extract.ts` 里那个 `truncated` 是**另一回事**（走查阶段超时、喂 `degraded`），没有动。

模型现在看到的两行：

```
truncated 这一页元素太多，**页面靠后的部分**没有列出，下面只是其中一部分
...
[表到此为止 · 页面后面还有 7 个元素没有列出]
```
