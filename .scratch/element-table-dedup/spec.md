## Problem Statement

用户问「n8n 这个仓库的 CI 是怎么配置的」，扩展指了一个和 CI 无关的控件，然后在原地打转，最后什么也没指到。

从用户视角看，症状有四种，都在 14 轮真机里出现过：

- **明明屏幕上有的入口，扩展说没有。** 用户停在文件列表中间时，仓库导航条在屏幕上方，扩展就当它不存在。
- **扩展要求用户先自己找到目标，再来问它目标在哪。** 只有滚到导航附近，导航才被指得出来——这把产品的因果关系倒过来了。
- **已经到了，扩展不承认。** 用户站在 issue 列表页上，扩展仍在给下一步，而不是说「到了」。
- **一次不痛不痒的输出格式失误，整轮作废。** 模型写了一个不在枚举里的动作名，之后就一直重复同一个已经被证明走不通的步骤。

对开发者，问题是**看不见**：`recall@budget` 这条 ≥95% 的硬门槛长期全绿，而它的 21 个 fixture 里最大的只有 7 个控件，从来没有一个碰到过 150 的预算。门槛名字里的 `@budget` 是空头支票，真正的病灶在门槛的盲区里。

## Solution

**不再试图判断「哪些元素更重要」，改为只删掉「同一件事说了两遍」。**

送给模型的元素表按三步收敛，顺序固定：

1. **无损去重** —— 删掉 `Restatement`：从 title/href/testid 猜出的兜底名重复了同页某条真名，或一个包装节点只裹着一个可交互子节点。删完不丢任何一个可点目标。
2. **地标保底** —— 导航类地标里的元素永不被裁，无论页面多大。
3. **尾部切片** —— 仍然超预算才按文档顺序切掉末尾，并在表尾写明切掉了多少。

视口完全退出裁剪决定，打分函数删除。预算提到 400 条，从「每次都在生效的裁刀」变成「只有极端页面才碰得到的护栏」。

同时补三个小口子：模型说「到了」时要有工具说得出口（`Sighting goal` 的判据松绑）；说了等于没说的 `observe` 动作删除；输出被校验拒绝时走一次修复轮，而不是抱着一份废计划继续。

对开发者，把现成的 `recall@budget` 指标搬到一个**会疼**的 fixture 上——一个仓库页形状、约 350 候选的大页面。它今天就该红。

## User Stories

### 被引导的用户

1. 作为一个停在页面中段的用户，我希望扩展能指出屏幕上方的导航项，这样我不必先自己滚到那里去。
2. 作为一个问「CI 怎么配置」的用户，我希望扩展能指到 `Actions`，即使我说的词和页面上写的词对不上。
3. 作为一个用中文提问、看英文页面的用户，我希望我说哪种语言不影响扩展能不能找到入口。
4. 作为一个要看「历次发布版本」的用户，我希望 `Releases` 稳定地出现在候选里，而不是十次里只有一次。
5. 作为一个在大页面上求助的用户，我希望扩展不会因为页面元素多就把导航整段丢掉。
6. 作为一个已经到达目标页的用户，我希望扩展告诉我「到了」，而不是继续给下一步。
7. 作为一个目标是「看到某个东西」的用户，我希望东西显示在这一页上就算完成，不必再多点一次。
8. 作为一个目标是「完成某个操作」的用户，我希望扩展不会在我只是看见了地址时就宣布完成——该指的复制按钮还得指。
9. 作为一个被指了一步的用户，我希望这一步之后引导会继续，而不是无声地冻结在那里。
10. 作为一个用户，我希望不会看到「这一步看起来没有反应」之后就再也没有下文。
11. 作为一个用户，我希望模型的一次输出格式失误不会让整轮引导作废。
12. 作为一个用户，我希望扩展在只能看到页面一部分时诚实地说出来，并说清楚缺的是哪一部分。
13. 作为一个在虚拟滚动列表里找东西的用户，我希望扩展仍然能让我滚到那些还没渲染出来的行。
14. 作为一个在登录页上的用户，我希望敏感输入框依旧不被引用、不被填写、不被高亮。
15. 作为一个模态框里的用户，我希望抽取仍然收窄到模态框内，不被本次改动破坏。
16. 作为一个用户，我希望这些改进不会让扩展变得明显更慢或更贵。
17. 作为一个跨页走多步的用户，我希望每一跳都基于当前这一页的完整候选，而不是基于我恰好滚到哪里。
18. 作为一个反复问同一个站点的用户，我希望同一页的连续调用仍然能命中缓存。

### 模型（元素表的消费者）

19. 作为模型，我希望表里不出现同一个目标的三份不同写法，这样我不必猜哪一个才是能点的。
20. 作为模型，我希望我需要的导航项在表里，这样我不必在 `why` 里写「这些标签不在当前元素表列出范围内」然后退而求其次。
21. 作为模型，我希望我判断出「已经到了」时有一个工具能说出口，而不是被迫发一个不会产生任何事情的步骤。
22. 作为模型，我希望我的输出被拒时能知道哪里不对并改一次，而不是让上一份废计划继续生效。
23. 作为模型，当表不完整时，我希望知道**缺的是页面靠后的部分**以及缺了多少，而不只是「不全」。

### 维护者

24. 作为维护者，我希望有一个今天就是红的、秒级的测试，这样修复有一个能对话的对象。
25. 作为维护者，我希望 `recall@budget` 这条门槛真的被预算约束，否则它绿着也没有意义。
26. 作为维护者，我希望知道「模型说它要的东西不在表里」还发不发生，且这个信号是从运行数据里读出来的，不是从症状反推的。
27. 作为维护者，我希望裁剪的丢弃位置是可预测的（永远是页面靠后），而不是随用户滚到哪里漂移。
28. 作为维护者，我希望删掉的死代码真的被删掉，而不是留一个没人调用的打分函数。
29. 作为维护者，我希望 eval 语料在这次形状变更之后被重新捕获，而不是留着一批与产品行为不符的期望值。
30. 作为维护者，我希望改动分层落地，每一层都能单独跑绿，而不是攒成一个大改动一次性验证。

## Implementation Decisions

### 投影模块（`project`）

- `prune` 从「打分排序取前 N」改为固定三步：**去重 → 地标保底 → 尾部切片**。函数签名保持 `(view, budget) → PromptTable`，这是本批改动能站的最高接缝，不新增。
- **去重判据**只回答「这两条是不是同一个目标」，不看角色重要性、不看与目标的关系，因此与用户语言无关。两条判据（对齐 Playwright MCP 蒸馏插件里可移植的那两条）：
  - 兜底名（`~` 标记，来自 title/href/testid）的名字重复了同页某条真名的开头 → 删兜底名那条；
  - 一个节点只裹着一个可交互子节点且自身不可点 → 拆掉包装、保留子节点。
- 判据来自真机实测的这个形状，一个提交产生四条 ref，其中两条是复述：

  ```
  e73 link "docker, (Directory)"
  e74 link "ci: Improve pnpm install performance (no-changelog) ("
  e75 link "#37789"
  e76 link ~"ci: Improve pnpm install performance (no-changelog) (#37789)"
  ```

  `e76` 是 `e74` 的复述（兜底名含 `e74` 的全文）；`e73`/`e75` 是各自独立的目标，必须留下。
- **地标保底**复用现成的 `LANDMARK_ROLES`——它已经是抽取期决定「谁进候选集」的判据，此处不引入新词汇。
- **尾部切片**按文档顺序，丢弃位置固定在页面靠后。这也是 `scrollIntoView` 正反馈自动消失的原因：文档顺序与滚动位置无关，因此高亮模块无需改动。
- `score()` 与 `viewportBands` **删除**，不留兼容路径。`PromptTable` 从此完全不含视口信息，与 `CONTEXT.md` 里 `Element table` 的定义重新一致。
- 元素条数保持为预算单位——`guide` 工具 `steps[].ref` 的 enum 必须与表一一对应，改成字符或 token 预算会让 enum 大小不可控。
- 64k 上下文档位的预算从 150 提到 **400**。其余档位按同一理由复核。

### 序列化（`toPromptText`）

- 表头 `truncated` 一行改为指明**缺的是页面靠后的部分**，而不只是「不全」。
- 表尾新增一行，带确切数字：形如「表到此为止 · 页面后面还有 N 个元素没有列出」。位置在表尾是刻意的——它是模型读完表后看到的最后一样东西，紧邻它要做决定的地方。
- 未截断时表尾一行不出现，表头 `truncated` 一行也不出现（保持现状）。
- 提示词里描述表格标记的那一段（`MARK_GUIDE`）必须与序列化器的真实输出逐字一致，不能是转述。

### 模型契约（`guide` 工具 schema）

- `observe` 从 `steps[].action` 的 enum 中**删除**，并从校验器接受的动作集合中删除。
- 问答路径直接构造引导步骤、不经过这个 schema，`observe` 在那一侧保留，`UserAction` 类型本身不变。
- `scroll` **保留**：虚拟滚动的行根本不在 DOM 里，滚动是唯一能让它们出现的办法，这不是裁剪能解决的问题。

### 提示词（`TOOL_CHOICE_POLICY`）

- 「目标涉及的东西出现在页面上，只说明看得见，不说明做完了」这一条**限定到 `Acting goal`**。它防的是「目标从没开始就 done」（历史上 7/14 轮），必须保留，但不能压在 `Sighting goal` 上。
- **不加** browser-use 式的 done 前检查清单：他们那六条是用来抵消 `success: bool` 默认 True 的，而 `done.evidence` 是必填枚举、没有默认值可抵消。且本项目已有记录：长的语义描述会把模型带偏。
- 不改动 schema，不新增字段——`done.evidence` 的三个枚举值已经把 `Sighting goal` / `Acting goal` 的分野做完了。

### 运行循环（`Repair call`）

- 校验失败（`violation`）与解析失败（`parse_error`）走**同一条**修复轮：把上一次输出与哪里不对作为最小对话喂回去，**恰好一次，绝不成环**。
- 现状是 `violation` 只标了「可重试」而无人消费，两次真机 violation 各报废一整轮。
- 修复轮仍然不含页面内容，维持现有约定。
- 归约器一侧的行为不变：修复轮跑在面板的运行循环里，纯归约器仍然只看最终结果。

### 诊断

- 追踪里新增一个事件：模型在 `why` 里表示「我需要的东西不在表里」时记录下来。**只诊断，不改变行为**——它是「裁剪修好了没有」的度量，不是给模型的新出口。
- 不给 `guide` 加「表里没有」的 schema 出口：如果裁剪修对了，那条出口就是死代码。

### 不变量（必须仍然成立）

- 独立重写的溯源扫描器不共享任何解析代码，逐字符核对模型输出的每个标量都能在原文找到。
- 元素表的 nonce 包裹不变，nonce 仍在抽取之后生成。
- 敏感元素仍出现在表里（诊断需要）但永不可高亮、永不被引用、永不被写 `value`。去重与保底都不得改变这条。
- 归约器仍是纯函数，会话存储仍只有宿主进程可写。
- 元素身份（`nth`、`path`）在**全集**上确定，与裁剪结果无关——本批改动不得让身份依赖于哪些元素活下来。

## Testing Decisions

**什么是好测试**：只测外部行为。投影模块的外部行为是「给一个页面视图和一个预算，表里有没有那个目标」；不测打分中间值、不测内部遍历顺序、不断言实现细节。

### 特性级接缝（主接缝，唯一新增测试资产）

`tests/eval` 现成的三段式（抓取 → 语料 → 记分）不改结构，**加一个大 fixture**：

- 手写 HTML，仓库页形状，约 350 个候选：顶部导航条（Code / Issues / Pull requests / Actions / Releases）、中段约 39 组文件行、底部贡献者与语言占比。每组文件行复刻上面那个「一个提交四条 ref」的形状，让去重有确定的东西可删。
- 标注七个目标，对应真机那七类用户目标的正确入口。
- 现成的 `recall@budget`（门槛 ≥95%）在这个 fixture 上**今天必须是红的**——导航被文件行挤掉。改完必须是 100%。

选它做主接缝的理由：它直接量根因（正确入口在不在表里），秒级、确定性、无网络；而真机一轮 20 分钟、n=14，方差大到分不出「抽样」和「退步」，不能当迭代的反馈回路。

现有 21 个 fixture 的语料需要**全部重新捕获**——表的形状变了。语料变更必须逐个看过，不是盲目覆盖。

### 模块级接缝（全部沿用现成 spec 文件，不新增接缝）

| 关注点 | 接缝 | 现成先例 |
|---|---|---|
| 去重、地标保底、尾部切片、预算、表尾一行 | 投影模块的纯函数测试 | 该模块已有整套 spec，含「整份输出的确切形状」这类逐字断言 |
| `observe` 从 schema 删除 | 契约与提示词的 spec | 已有工具 schema 断言与信封解析测试 |
| `done` 提示词限定 `Acting goal` | 提示词 spec | 已有对提示词字面内容的断言 |
| `violation` 走修复轮 | 运行循环 spec | 已有 `parse_error` 修复轮的测试，照同一形状加 |
| 诊断事件 | 追踪 spec | 已有事件种类断言 |
| `PromptTable` 不含视口信息 | 架构守卫 spec | 已有跨模块守卫（如「面板不得写会话存储」） |

### 回归

- 敏感元素、模态框收窄、影子 DOM、`iframe`、虚拟滚动这些既有 fixture 的 `recall` 与歧义率不得下降。
- 端到端套件全绿。
- 元素身份不随裁剪结果漂移——已有针对这一点的测试，必须仍然通过。

### 最终确认（不是迭代门槛）

全部做完之后跑一次真机（7 类目标 × 2 遍），由用户按「最终 URL + 最后一步」人工判定到达。**规格不把它当作迭代中的门槛。**

## Out of Scope

- **不引入目标相关性剪枝。** 词法打分实测在七个目标里丢掉五个正确入口；跨语言的相关性需要专门训练的模型，本批不做。
- **不引入交互式检索**（让模型二次索要页面内容）。它建立在「多次往返 + 对话累积」上，而本项目每次调用都是全新的两条消息，一次往返就是一次全量提示。
- **不抄视口硬过滤，也不抄「你看到的只有视口内的」那类说明**——那描述的是我们决定不再具备的限制，对我们是假话。
- **不加达成判断的必填字段。** 四个一手来源里没有先例，且 `done.evidence` 已经承担了这个分类。
- **不加 done 前检查清单。**
- **不改高亮模块**：正反馈随裁剪判据变更自动消失。
- **不动问答路径。**
- **不做结构折叠**（把同构列表压成一行摘要）——那是有损的，用户想点某个具体条目就点不到了。
- **不重新冻结真机门槛基线**，也不在本批里调整既有的六道真机门槛。
- **不执行任何 git 操作。**

## Further Notes

- 本规格推翻的是投影模块里整段打分注释所依据的前提，ADR 0012 已记录推翻理由与证据。实现时那段注释必须一并重写，不能留下与代码矛盾的说明。
- 成本预期：真机拟合 `prompt ≈ 25.8 × 元素数 + 2593`。仓库主页从截断的 150 条（约 6300）变为去重后约 234 条（约 8900），单次约 +41%。这是已经接受的代价，换 20/20 截断归零。若实测涨幅显著超过这个数，说明去重没有生效，应当先查去重而不是先调预算。
- 分层顺序建议：先让主接缝红起来（大 fixture + 标注），再动投影模块，最后收契约、提示词、运行循环与诊断。每一层单独跑绿，符合「从端到端可运行的最小版本开始」。
- 「模型说它要的东西不在表里」这个诊断事件，是判断本批是否真正修好的唯一运行时证据。真机跑完之后应当为零。
