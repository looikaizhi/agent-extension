# 规格 C：三个实验的结局（2026-09-27 结帐）

这份规格拆的是三件事：**Workflow**（回放上次走通的路）、**Memory**（把上次走通的路念给模型听）、**新站点 Skill**。结局各不相同，记在这里，免得以后有人照着规格重来一遍。

## Workflow —— 不做

三条理由叠加，任何一条单独都不足以否掉它：

1. **定位矛盾**：回放只在「同一个人、同一个站、同一个目标、反复做」时回本，而产品的定位是**陌生**的 Web 控制台。熟到会反复做，用户已经不需要指路。
2. **最该回本的那类任务最不能回放**：值得存的是「少做、步骤多」的事，而那正是页面最可能已经改版的那类。实测：**71% 的跳在这一步之后页面就变了**（t09 + t11 共 130 趟、382 跳）。回放一撞上变化就得交给模型重新规划——那一刻它就只是「带着线索的引导」。
3. **它要的引擎已经删了，而且删对了**：「多步、不调用模型、用户用过才前进」就是 `Fixed plan`（166 行 + 13 处分支，服务一个只发一步的功能）。见 `.scratch/one-plan-source/issues/01`。

另外这份规格**自己的验收机制也不在了**：23–29 号用户故事全是「在评测上量出提升才合进来」，而 2026-09-25 定了不再跑测评。

## Memory —— 做过，2026-09-27 删掉

第一版落地过（`agent/context/memory.ts` + 侧栏「它记住的路」+ 念给模型的那一段），但与规格差了四处，四处都偏向「更多、更松、没量过」：

| 规格 | 实现 |
|---|---|
| 只有用户答「到了」的那一趟才有资格 | `ending === 'model_done'`——实测只有 **71%** 真到了 |
| 只取**一条**、目标最接近的 | 取**最近 3 条**，不看目标 |
| **默认关闭**，直到量出提升 | `defaultOn: true` |
| 效果由配对评测量出 | **一次都没量过** |

关于最后一条，查过所有记录：每一轮真机开的都是 `['skill']`（memory 那时还不在登记表里）；离线三轮带着它的是 3 条 / 4 条状态的冒烟，语料与指纹都不同，构不成配对比较。

完整的「为什么删」写在 `CONTEXT.md` 的 `Memory` 词条后面。**留下的**：`Run record`（它是原料，不是 Memory 本身）与 `Plugin` 接缝（`Skill` 还在用）。

## 新站点 Skill —— 还没做

gitee.com 与 help.aliyun.com 的站点技能没写。这一条与上面两条不同：它不依赖任何被删掉的机制，只是没排期。但它的验收（28 号故事）同样写的是「离线配对比较」，而那个前提也不在了。

## 还站得住的那一块：地基

1–4 与 22 号故事——**引导结束时问一句「到了吗」，答案写进 Run record**——不依赖 Workflow 也不依赖 Memory，而且它修的是一个可以直接量出来的错误率（上面那个 71%）。它同时会给产品**第一份真实的 Arrival 数据**：今天 `check` 是模型自己预测自己，`confirmation` 只说「点了、页面变了」，没有一处是用户说的。

要不要做，另开一票。
