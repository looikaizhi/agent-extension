# 规格 C：Workflow、Memory 与新站点 Skill 的第一版

**Status:** parked（2026-09-15，你定：不是必须的，将来可能扩展时再用）

现在不做，也不为它预先搭接缝。扩展点已经有了：规格 A 的 Plugin 机制，加一个就是一个目录加一处登记。以后任何一项要做，都照 `evals/README.md` 的流程证明有效：先在 Decision eval 上对照基线，再真跑确认。下面的调研与设计决定都保留，重启时从这里接着做。

| 部分 | 什么时候值得重新拿出来 |
|---|---|
| 结束时问「到了 / 没到」 | 需要真实使用中的到达数据时（例如准备给外部用户用之前），或者要做 Workflow 时（它是 Workflow 的前提） |
| Workflow（照上次走通的路回放） | 真实使用里同一个人在同一个站点反复做同一件事，或者模型调用的成本、延迟成了问题 |
| Memory（参考上次走通的路） | 同一站点上反复出现同一类错误，而改提示词修不掉；并且 Decision eval 显示还有提升空间 |
| 新站点 Skill | 架构成熟之后（Skill 不是主力），并且某个站点的失败主要是模型认不出这个站的叫法 |

> 来源：`.scratch/agent-architecture/decisions.md`（2026-09-12 用户确认）与 `docs/research-agent-skills-workflows-memory.md`。词汇以 `CONTEXT.md` 为准。依赖规格 A（Plugin 机制、目录结构）与规格 B（两层评估、Plugin 开关）。**这里的每一项都是一次实验：通过评估才合进来，它的目录才出现。**

## Problem Statement

**对用这个扩展的人：**
- 每一趟引导都从零开始。上周走通过的路，这周同一个目标还要重新花一样多的模型调用，也可能走出不一样的结果。
- 产品从来不问你「到了没有」，所以它无法分辨哪一趟值得记住。
- 站点技能只有 github 一份，别的站点上模型对这个站怎么称呼东西一无所知。

**对产品的主人：**
- 你希望 memory、skill、workflow 这些目录里的功能对 agent 真的有效。
- 外部研究说它们的效果时正时负：在更强的模型上，有几项反而低于不用；取的经验越多效果越差；browser-use 发布过 memory 又把它关掉、删掉。
- 在「只指路、人来动手」的设置下没有人测过。
- 所以「有效」只能在我们自己的评估上量出来，并且要能单独开关、单独比较。

## Solution

先打一块共用的地基，然后三个实验依次进行，每个都做成可以单独开关的 Plugin：

- **地基**：引导结束时问一句「到了 / 没到」；Run record 的每一步补记足够回放和回忆的信息。只有你答「到了」的那一趟，才有资格被写成 Workflow 或 Memory。
- **Workflow（先做）**：你开始引导时，侧栏列出这个站点上最接近的几条「上次走通的路」，你点了才照着走。回放不花模型调用；某一步找不到目标时，交给模型接着规划。
- **Memory（后做）**：模型规划时，给它看同一站点上最接近的一趟「上次走通的路」作参考。只取一条，写明页面可能已变。
- **新站点 Skill**：为 gitee.com 和 help.aliyun.com 写站点技能，量它们有没有帮助。

## User Stories

1. 作为用这个扩展的人，我希望引导结束时侧栏问我「到了 / 没到」，这样产品知道哪一趟真的走通了。
2. 作为用这个扩展的人，我希望可以不回答，不回答就什么都不存，这样我不会被逼着回答。
3. 作为用这个扩展的人，我希望关掉标签页那种结束不再问我，这样问题不会出现在我已经离开的地方。
4. 作为用这个扩展的人，我希望打转兜底把引导停下时也问我，这样我确实到了的时候，这一趟不会因为模型没说 done 就被丢掉。
5. 作为用这个扩展的人，我希望在一个站点上开始引导时，看到至多 3 条「照上次走通的路走：……」，这样重复的目标可以一键照走。
6. 作为用这个扩展的人，我希望只有我点了才回放，这样产品不会自作主张地走一条错的路。
7. 作为用这个扩展的人，我希望不点建议时，引导照常由模型规划，这样建议永远不会挡路。
8. 作为用这个扩展的人，我希望回放时每一步仍然等我用过才前进，这样回放和平时的引导手感一样。
9. 作为用这个扩展的人，我希望回放不花任何模型调用，这样照上次的路走是免费的。
10. 作为用这个扩展的人，我希望回放到某一步找不到目标时，产品交给模型接着带我，这样页面变了也不会停在原地。
11. 作为用这个扩展的人，我希望交给模型时它知道「上次这一步是 X，这次找不到」，这样模型不必从头猜。
12. 作为用这个扩展的人，我希望从检视器交来的步骤仍然永不调用模型，这样那条零成本的承诺不被回放功能改掉。
13. 作为用这个扩展的人，我希望模型规划时参考我在同一站点上一次走通的类似的路，这样它少走弯路。
14. 作为用这个扩展的人，我希望模型每次只参考一条，并且被告知页面可能已变，这样旧经验不会压过眼前的页面。
15. 作为用这个扩展的人，我希望正在回放时不再额外参考 memory，这样两样东西不会互相打架。
16. 作为用这个扩展的人，我希望在侧栏的「记忆」区看到产品记住了哪些路，这样我知道它记了什么。
17. 作为用这个扩展的人，我希望能逐条删除记忆、也能一键清空，这样我的浏览记录由我做主。
18. 作为用这个扩展的人，我希望每个站点只留最新 20 条记忆，这样存储不会无限长。
19. 作为用这个扩展的人，我希望在设置里单独开关 Workflow 和 Memory，这样我不想要的能力可以关掉。
20. 作为用这个扩展的人，我希望在 gitee.com 和 help.aliyun.com 上，模型也知道这个站怎么称呼东西，这样在这两个站上引导也能少走弯路。
21. 作为产品的主人，我希望 Run record 的每一步记下 Descriptor、动作、建议输入的值、在哪一页提出、落到了哪一页，这样一趟走通的路可以被回放、被回忆、被评估读懂。
22. 作为产品的主人，我希望「到了吗」的回答写进 Run record，这样它既是写入的闸门，也是真实使用中的 Arrival 数据。
23. 作为产品的主人，我希望 Workflow 与 Memory 默认关闭，直到它们各自在评估上量出提升，这样没证明有效的东西不会默认影响用户。
24. 作为产品的主人，我希望 Workflow 的效果在真机评估里量：第一遍到了就存下，第二、三遍回放，要求 Arrival 不显著变差、回放那几遍的模型调用接近零，这样「省钱且不变坏」有证据。
25. 作为产品的主人，我希望真机评估无人值守时，由程序化判据代答「到了吗」，事后用我的判定核对，这样实验可以自动跑完。
26. 作为产品的主人，我希望 Memory 的效果在离线评估里量：同一批状态带 / 不带 memory 做配对比较，memory 必须来自别的目标，这样量出来的是泛化，而不是把答案递给了它。
27. 作为产品的主人，我希望 Memory 在真机评估上只需确认不退步，这样闸门落在分辨率高的那一层。
28. 作为产品的主人，我希望新站点 Skill 在离线评估上量：同一批这两个站点的状态，带 / 不带技能做配对比较，这样知道 Skill 不只在 github 上有效。
29. 作为产品的主人，我希望任何一个实验量不出提升就不合进来，它的目录也不出现，这样树里每个目录都对应一个被证明有效的功能。
30. 作为产品的主人，我希望不带 memory 时，发给模型的东西和之前逐字节一致，这样「关掉 Memory」真的等于什么都没改。
31. 作为产品的主人，我希望 Workflow 和 Memory 都通过规格 A 定的接缝接入主流程，不在归约器里写死，这样以后的能力照同样的方式接进来。
32. 作为之后做 skills 下一步的人，我希望「由模型挑选、按需读全文」的触发条件已经写下来，这样我知道什么时候值得做它。

## Implementation Decisions

**Plugin 接缝**：本规格引入规格 A 预留的另外两处接缝，各由第一个用到它的 Plugin 带进来。
- **引导开始时给建议**：Workflow 用。
- **一趟结束、「到了吗」有了回答时拿到这一趟的 Run record**：Workflow 与 Memory 的写入用。

Memory 的读取走规格 A 已有的「往 Context 加一段」。三处接缝都在归约器之外。

**地基**
- **「到了吗」**：
  - 引导进入终态、并且侧栏开着时，侧栏出一张卡片：「到了 / 没到」。关标签页那种结束不出现。
  - 可以不答，不答 = 没有资格被写入。
  - 回答写进这一趟的 Run record。
- **Run record 每一步补记**：Descriptor、动作、建议输入的值、在哪一页提出、落到了哪一页。仍受每条上限与总配额约束，写之前照旧先查配额。

**Workflow**
- **生成**：一趟被答「到了」时，从它的 Run record 生成一条 Workflow，按站点存下。
- **建议**：
  - 你在某个站点开始引导时，列出这个站点上目标最接近的至多 3 条。
  - 「最接近」用现有的中英文分词算词重叠，只用来排序；拍板的是你。
- **回放**：
  - 归约器新增一种计划来源「workflow」。
  - 前进规则与 Fixed plan 相同：只在用户用过这一步、或按了跳过之后前进；不调用模型。
  - 某一步在现有的等待窗口里找不到目标时，交给模型接着规划。交出时，上下文带上「上次这一步是什么、这次在哪一页找不到」。
  - 检视器的 Fixed plan 保持「永不调用模型」，一个字不改。
- **Evidence**：回放那一趟的 Evidence 取什么，在实现时对照词汇表的四个取值定。它来自走通过的路，所以候选是 `walked`。

**Memory**
- **写入**：只在一趟被答「到了」时写。内容原样取自 Run record：目标、站点、每一步的标题与落到的页面、终点。不经模型加工。
- **存储**：`storage.local`，每个站点保留最新 20 条。
- **读取**：
  - 规划时只取同一站点、目标最接近的 1 条，接近程度要过门槛才用；正在回放 Workflow 时不取。
  - 放在 user 消息里：站点技能之后、不可信的页面内容之前。标明「你上次在这个站点完成类似目标时走过的路，仅供参考，页面可能已变」，并限制长度。
- **管理**：侧栏「记忆」区能看、能逐条删、能清空。第一版不做自动降级。

**新站点 Skill**：为 gitee.com 和 help.aliyun.com 各写一份站点技能，形状和 github 那份相同，按域名加载。

**开关与默认值**
- Workflow 与 Memory 各是一个 Plugin，默认关；新站点 Skill 跟随 Skill 这个 Plugin 的开关。
- 设置里可以单独开关每一个。
- 某一项通过评估后，由单独一次改动把它改成默认开。

**实验与合并规则**

| 实验 | 在哪一层量 | 算有效的条件 |
|---|---|---|
| Workflow | Task eval：每个目标第 1 遍到了就存下，第 2、3 遍回放；无人值守时「到了吗」由程序化判据代答，事后用人工判定核对 | Arrival 不显著变差，并且回放那几遍的模型调用接近零 |
| Memory | Decision eval：同一批状态带 / 不带做配对比较，memory 来自别的目标；Task eval 确认不退步 | 意图或第一步准确率显著提升，Task eval 不显著退步 |
| 新站点 Skill | Decision eval：这两个站点的状态带 / 不带技能做配对比较 | 同上 |

- 量不出提升 = 不合进来，目录也不出现；改了之后可以再试。
- **顺序**：地基 → Workflow → Memory → 新站点 Skill。

**以后的事**：由模型挑选、按需读 Skill 全文的触发条件是：某个站点的技能超过约 1500 token，或者同一站点有 3 份以上各管一件事的技能。到那时它是 `tools/` 里的一个 Tool。

## Testing Decisions

- **好的测试只断言外部行为**：归约器对输入给出的状态与效果、宿主写进存储的东西、发给模型的消息、侧栏上出现的东西。
- **归约器 `step()`**：覆盖计划来源「workflow」，写法和 Fixed plan 现有的那组用例相同。
  - 用过才前进；跳过就前进；
  - 全程零模型调用；
  - 找不到目标时交给模型，并且带上「上次这一步」的上下文；
  - Fixed plan 的原有用例一条不改、全部通过。
- **宿主那层的注入式测试**：
  - 「到了吗」的回答写进 Run record；
  - 答「到了」才写 Workflow 或 Memory，答「没到」和不答都不写；
  - 每一步补记的字段齐全；
  - 配额不足时照旧明确报错。
- **纯函数**：
  - Workflow 建议的排序（同站点、至多 3 条、目标越接近越靠前）；
  - Memory 的取用（1 条、过门槛才用、回放时不取）；
  - 每站 20 条的上限。

  存储按 Run record 那样注入。
- **规格 A 的快照切面**：
  - 带 memory 时，那段文字出现在约定的位置、带着约定的提示语、没有超长；
  - **不带 memory 时，与之前逐字节一致**；
  - 新站点 Skill 只在对应域名出现。
- **e2e**：
  - 引导结束后出现「到了吗」卡片，关标签页时不出现；
  - 在有 Workflow 的站点上开始引导，出现建议；点了之后回放全程零模型调用；
  - 记忆区能看、能删、能清空；
  - Plugin 关闭时，以上入口都不出现。
- **先例**：Fixed plan 的归约器用例、宿主终结流程的注入式测试（已经记录存储调用顺序）、现有快照与 golden 语料的写法、问答与引导的 e2e 断言风格。

## Out of Scope

- 让模型把走过的路提炼成经验条目：只有原样版本量不出提升时，才作为下一次实验。
- 某条 memory 被用过的那一趟答了「没到」就自动删掉它：第一版不做。
- 由模型挑选、按需读 Skill 全文（触发条件见上）。
- LLM 评审代替人工判定。
- 跨设备同步 Workflow 与 Memory。
- 自动回放（不经用户点选）。

## Further Notes

- **外部研究的数字**：
  - AWM 在 Mind2Web 的逐步设置上，把元素准确率从 41.6 提到 50.6，但动作 F1 从 60.6 降到 57.3；
  - ReasoningBank 复现的 AWM 在 Claude-3.7 上从 41.7 降到 40.8；
  - 取 1 条经验时 49.7，取 4 条时 44.4。

  这些决定了本规格的三个选择：只取一条、用人的回答当写入闸门、默认关闭直到量出提升。
- **回放要能交还给模型**，依据是：做确定性回放的几家都设计了回落，唯一关掉回落的那家在自己的说明里写着「currently really bad」。
- **为什么先做 Workflow**：它的收益最直观（回放零调用），风险最低（走不通有模型接手），而且它会先把「到了吗」和 Run record 补记这两块共用的地基打好。
