# 06 — 归约器的帮手成为独立模块，纯度守卫改成按依赖闭包算

**What to build:**

为后面几张拆模块的票铺路，先把改动变容易。

- Tool 与 Output 的后果要用的帮手（画一步、给当前这一步盖章、通知、前进一步、发起模型调用和文档抓取的闸门）移进一个归约器和其它模块都能 import 的模块。
- 「归约器是纯的」这条守卫，范围从一个文件名改成「归约器在运行时能加载到的所有源码文件」，按依赖闭包计算。这样以后把逻辑搬出归约器，守卫不会悄悄失效。

**实现记录**
- 新守卫第一次运行就抓到了一个真问题：归约器按值 import 了 Run record 模块，而那个模块里有写存储的异步函数，所以归约器在运行时一直加载着 IO 代码，旧守卫只看一个文件名，看不到。已拆开：「是什么、怎么判」留在原来的 record 模块，「怎么存」单独成模块，四处 import 已同步修改。
- 闭包只跳过 `import type` / `export type`。本仓库开着 `verbatimModuleSyntax`，`import { type X }` 仍会加载模块，所以照样跟进去。
- 收尾时闭包共 16 个文件，包括间接加载的几个 `core/` 文件，全部通过 N-2。
