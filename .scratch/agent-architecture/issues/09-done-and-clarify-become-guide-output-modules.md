# 09 — done 与 clarify 成为引导的 Output 模块

**What to build:**

照第 08 张定下的形状，把引导 Agent 的 done 与 clarify 各做成一个 `Output` 模块，六样齐，并在登记处登记。

- done 的后果：Thread 终结，终结方式记为「模型说到了」。
- clarify 的后果：Thread 停下来等用户，步骤保留。

**Blocked by:** 08 — need_docs 成为第一个 Tool 模块

- [x] 归约器里不再有 done 与 clarify 的分支代码
- [x] 相关现有用例全部通过
- [x] 类型检查、单测、e2e、抽取器评测全绿，并且第 01 张冻结的快照逐字节一致

**实现记录**
- **done 与 clarify 各成一个 `Output` 模块**，放在引导 agent 旁边的 output 目录，六样齐：给模型的函数、系统提示词里自己那一段、识别、识别失败时的形状提示、认领的 ref、trace 理由、后果。done 的三个完成依据取值和它的信封类型一起搬进了 done 模块。
- **登记顺序是 clarify、need_docs、done**，正是今天模型读到的顺序。工具列表和提示词都由门面按登记顺序拼出：原来夹在开头那段末尾的 clarify 那一条、收尾那段开头的 done 那一段，都拆给了各自的模块；done 那段提示词背后的来由注释也一起搬了。
- **删掉的分支**：归约器里 done 与 clarify 的两个分支，改由登记处分派；共享识别里 done 的分支与形状提示；校验与 trace 里 done 的分支，以及 trace 里 clarify 的分支。
- **clarify 的形状、识别和认领的 ref 仍留在契约里**，两个 agent 共用（Q9）。clarify 模块只引用它们，校验也改用同一个函数，不再各写一份。
- **快照逐字节不变。**
- **登记测试扩到三个模块**：清空登记处后，工具只剩 guide，三个模块的提示词段都不在；need_docs 与 done 在两条识别路径上都被拒。clarify 不在拒绝之列：它的形状与问答共用，契约照样认得；去掉登记，去掉的是「把它提供给模型」和「按它行事」。
- **探针查出一处测试缺口，已补**：把 done 的后果改成不撤步骤，测试仍然全绿。原因是那条 done 测试从默认的空步骤出发，撤没撤步骤看不出来。现在改为带两步、停在第二步出发，并补断言游标归零、终结方式记为「模型说到了」。复测：不撤步骤、撤了步骤但不归零游标，两种改法都让它变红。
- **「终结方式记为模型说到了」目前落在 done 效果的来源上**：来源记为 model，和兜底停下、固定计划走完区分开。Run record 里「怎么结束的」这一栏由第 03 张加。
- **问答路径的边界变化**（第 08 张起就有）：done 也移出共享识别之后，问答回答里出现 done 会先走一次修复，而不是直接报「不支持的信封类型」。已写进第 05 张的验收，由问答自己的读回答恢复原行为。
