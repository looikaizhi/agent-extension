# 12 — Plugin 机制与 Skill

**What to build:**

引入 `Plugin`：一项有名字、有默认开关、可以单独开关的 agent 能力。这张票只引入「往 Context 里加一段」这一个接缝。

- 站点知识改名为 `Skill`，成为第一个 Plugin，默认开。
- 它的文字不再由归约器挑选，而是在归约器之外、发起模型调用时收集，随调用参数交给 Agent；文字和位置都不变。
- 开关存进设置（和 trace 开关同一类存储），harness 可以在跑之前写入。
- 每一趟的 Run record 记下开了哪些 Plugin。
- Pack 这个名字从代码里退场。

**Blocked by:** 03 — Run record 分开记「怎么结束」和「确认了几步」；06 — 归约器的帮手成为独立模块，纯度守卫改成按依赖闭包算

**实现记录**
- **Plugin 的接缝**：新增 agent 这一层的 context 目录，里面放 Plugin 接口与登记处。
  - 每个 Plugin 有名字、默认开关，以及「给某个网址的页面加一段话」这一个接缝。
  - 开关存在 `storage.local` 的 `plugin:<名字>` 下，与 trace 开关同一类存储；没写就按默认，读失败也按默认。
  - 加一个 Plugin = 它自己的目录 + 登记处里的一行。
- **Skill 是第一个 Plugin，默认开**：
  - 原来的 github 站点知识迁进 agent 的 skills 目录，按页面域名整段加载。
  - 「关于这个站点，你需要知道：」这句引子也归 Skill 自己，所以文字和位置都不变，快照逐字节一致。
- **收集在归约器之外**：
  - 归约器发出的模型调用不再带任何站点内容，帮手模块里的站点知识查询已删除。
  - 宿主在发出模型调用时读取开关、收集已开 Plugin 的贡献，随请求参数交给引导 agent。因为每次发调用都重新读，设置里改了开关，下一次调用就生效。
  - 架构守卫新增一条：Skill 与收集 Plugin 贡献的模块都不在归约器的依赖闭包里。
- **Run record 记下这一趟结束时开着哪些 Plugin**（harness 会在跑之前设好开关，之后不再改动，所以这就是这一趟用的那组）。
- **Pack 退场**：
  - Descriptor 的绑定与生成两个文件，按决策搬到 `core/descriptor/`（原定第 13 张做，为满足本票「代码里不再出现 Pack」提前做了），原来的 packs 目录删除。
  - 各处注释里的 pack 改成 Skill 或固定计划。
  - 词汇表删去 Pack 词条，Skill 词条改为已实现的第一版。
- **测试**：
  - 快照测试取站点技能改用 Skill 真正的收集函数，并新增一份「Plugin 全关」的快照。另有一条断言：全关时只少站点技能那一段，其余逐字节一致。
  - 原来的站点知识测试改写成 Skill 的测试，补上「归约器发出的模型调用不带任何 Plugin 内容」和开关的默认、关闭、读失败三种情况。
  - 宿主测试新增三条：Skill 默认开、关掉后下一次调用就不带；没有它的站点什么也不带；Run record 记下开着哪些 Plugin。
  - e2e 把 github.com 路由到一页本地夹具，核对请求体里照旧有站点技能那一段、关掉后下一次调用就不带、Run record 记下开着哪些 Plugin。
- **快照里两个用例名还叫「有站点知识」「站点知识、历史……」**：用例名印在快照文件里，改名会让冻结的快照变字节，所以保留。它们只是测试标签，不是发给模型的内容。

**评审后续**（两轴评审之后，按用户的「修」改）
- **Run record 按这一趟开始时的开关记**（Spec c1）：
  - 原来每次发调用时读开关，结束时再读一次记进 Run record。一趟中途改了开关，调用和记录就各说各的。
  - 现在一趟只用一组：开始时读开关，把名字存在线程旁边（`plugins:{线程}`，和线程、在途效果的镜像走同一个写队列、同一批写入）。这一趟的每次调用都用它，结束时记进 Run record，线程删除时一起删。
  - 所以设置里改了开关，从下一趟起生效，验收项的措辞随之改为「下一趟」。实现记录里「每次发调用都重新读」和「Run record 记下这一趟结束时开着哪些 Plugin」两句，由这一条取代。
  - e2e 原来靠「第一趟恰好在关开关之前结束」这个没写明的先后顺序，现在不再依赖它。
- **守卫按目录判定**（Spec c2）：skills 目录下的任何文件都不许进归约器的依赖闭包。收集模块仍按文件判定，因为 context 目录之后还会放其余的 Context 拼装。
- **开关只有一种读法**（Standards）：
  - `isFlagOn` 增加默认值参数：存了布尔就用，否则取默认，读失败也取默认。Plugin 的开关改用它，trace 开关的语义不变。
  - 依赖字段 `settings` 改名 `flags`，不再和存 provider 配置的 settings 撞名。
  - 测试里四份手写的假开关存储，合成一个共用夹具。
- **删掉没人读的 `SiteSkill.name`**；抽取器里有一句注释把 pack 时代的后果安到了 Skill 头上，删掉了它的后半句。
- **Pack 与「站点知识」清干净**：CONTEXT.md 的 Context 词条、「为什么只剩一套引导实现」一段与 Plugin 词条；一条测试名；e2e 两处注释；spike 两处注释；Run record 的头注释；教程里的目录树、历史一节、死链和术语表。
