# 05 — 问答 agent 有了自己的门面和运行循环

**What to build:**

页面问答的模型逻辑搬出侧栏的界面代码。

- 问答 Agent 有和引导同形状的门面：名字、说明、拼消息、回答形状、读回答、核对。
- 它有自己的运行循环：首次调用 → 解析 → 最多一次修复 → 核对。修复是一段不含页面内容的全新短对话，只修一次，不成环。
- 侧栏只负责触发、取消和显示。
- 问答仍用自由文本 JSON，不改用 tool calling。
- 做完之后，问答 Agent 能在 node 里被直接调用（规格 B 的评估要用）。

**Blocked by:** 01 — 冻结「发给模型的东西」快照；02 — 同一个取值只有一个所有者

**实现记录**
- **问答 agent 有了自己的门面**，与引导同形状：名字、说明（系统消息原文）、拼消息、回答形状（它用自由文本 JSON，所以回答形状是给模型读的那段说明，不是 schema）、读回答、核对。
- **问答 agent 有了自己的运行循环**：首次调用 → 读回答 → 读不出就修复恰好一次 → 再读 → 核对。
  - 两处调用 `complete` 仍是两个字面上分开的调用点，所以「最多修一次」是结构，不是计数。
  - 修复是一段不含页面的全新对话，引用首次回答的原文。
  - 结果分四种：答出、失败（网络 / 读不出 / 核对不过）、取消。
  - 进度（已收到多少字、正在修复、每次请求花了多少）以事件交给调用方，丢掉这些事件结果不变。
- **侧栏只负责触发、取消和显示**：不再直接调用模型、解析回答或发起修复。原来那段手写的「这不是问答的 intent」排除也删了。
- **问答回答里出现引导独有的 intent（guide / need_docs / done）**：读回答时就认出来，直接显示「模型返回了问答流程不支持的信封类型「X」。」，不发修复请求。不再先付费修复一次、再显示那句「信封的形状不合」的错话。这与第 08 张之前并不完全相同，那时有三种情况的结果不一样，现在都直接显示「不支持」：形状残缺的 guide 回答会先修复，有可能换回合法的 explain；指向敏感控件的 guide 回答显示 R-e 的理由；页面已经变了的显示「页面已经变化」。只有第一种少了一次可能的挽回，按票的写法接受。
- **问答 intent 的类型改从契约推出**：问答的三种 intent 用契约的 `Intent` 约束，引导独有的那几种由全部 intent 减去这三种得出。契约里手写的「问答三种信封」联合删了，侧栏的回答类型改用问答 agent 的。
- **问答 agent 能在 node 里直接调用**：新的运行循环单测就是这么调用的。
- **架构守卫**：「宿主不得依赖运行循环」扩到问答的运行循环。
- **问答快照改由运行循环驱动**，一个假的 complete 录下每次请求的消息和请求选项。第一个用例的提问前后带空白，快照那一段不变，证明提问在发出前去掉了首尾空白。修复请求取自运行循环真正发出的第二次请求，证明它引用的是首次回答的原文。
- **快照改了一行（有意的）**：原来那段「坏回答」少一个右花括号，解析器的截断修复其实能把它救回来，产品遇到它根本不会发修复请求，原快照记的是一次不会发生的请求。现在换成在字符串中间截断、真正救不回来的写法。快照因此只有修复请求里引用的那一行变了；产品自己写给模型的文字仍逐字节不变。问答快照哈希 523c9075… → 96778e10…，引导快照不变。
- **变异探针全部变红**（改完即恢复，文件哈希核对一致）：
  - 提问不去首尾空白 → 快照与运行循环测试红；
  - 修复请求没有原样引用首次回答 → 快照红；
  - 引导的 intent 当成坏形状去修复、取消后仍当成失败、网络错被说成解析错、不核对 → 运行循环测试红；
  - 不修复 → 运行循环测试与快照红；
  - 宿主依赖问答的运行循环 → 架构守卫红。
