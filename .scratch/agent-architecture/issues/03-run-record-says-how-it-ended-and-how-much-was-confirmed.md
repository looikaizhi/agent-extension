# 03 — Run record 分开记「怎么结束」和「确认了几步」

**What to build:**

一趟引导的记录，今天用一个值同时说两件事：`abandoned` 既表示「一步都没确认」，也表示「被强行停下」；打转兜底又直接写成「部分完成」。拆成两个字段：

- **怎么结束的**：模型说到了、步骤走完了、打转兜底、配额用完（模型调用或文档抓取）、跨站凭据停止、用户结束、关浮层、关标签页、被同一标签页上新的一趟接替。
- **确认了几步**：全部、部分、一步都没有。只按历史机械计算，与结束方式无关。

旧的单一状态值删除，不留兼容。读它的地方（侧栏、e2e、真机脚本的打分）一并改用新字段。「从 active 变成非 active 就终结」这条判据不变。

**实现记录**
- **Thread 与 Run record 不再有单一的状态值。** Thread 改带一个「怎么结束的」字段，没有这个字段就表示还在进行中；原来的「放弃原因」字段一起删除。结束方式共九种：
  - 归约器自己走到的五种：模型说到了、步骤走完了、打转兜底、配额用完（模型调用与文档抓取共用这一种）、跨站凭据停止；
  - 宿主从外部结束的四种：用户结束、关浮层、关标签页、被同一标签页上新的一趟接替。
- **「确认了几步」只按历史机械计算**：全部、部分、一步都没有。与结束方式无关，Run record 同时记这两个字段。
- **宿主结束一趟进行中的引导时，由调用方说明是哪种外部结束**：后台四个结束入口各自传入自己的那一种。归约器已经记下结束方式的，以归约器的为准。「这次归约让这趟引导有了结束方式，就终结」这条判据不变（原来是「从 active 变成非 active」）。
- **固定计划走到头时**，结束方式记为「步骤走完了」；结束语仍按「是否全部确认」来说「走完了」或「有几步没有走通」。
- **删掉的死字段**：通知效果里的「原因」没有任何地方读，一并删除。
- **测试**：
  - 确认程度改为按历史的单测；
  - 「前几步已确认、随后撞上配额」在记录层和宿主层各有一条，都断言「配额用完 + 部分确认」；
  - 同一段历史配九种结束方式，确认程度都相同；
  - 宿主层的结束测试补齐：五种终态各一条（新增「步骤走完了」），四种外部结束各一条，都核对摘要里记下的结束方式与确认程度。
- **e2e 和真机脚本改读新字段**：e2e 断言这趟记为「模型说到了 + 一步都没有」，并且记录里已经没有旧字段；真机脚本打印的是结束方式和确认程度。
- **快照**：两份都逐字节不变。
- **变异探针全部变红**（改完即恢复，文件哈希核对一致）：
  - 确认程度看结束方式、确认程度看游标不看历史 → Run record 测试红；
  - 配额记成凭据停止、打转兜底记成模型说到了、固定计划走完记成模型说到了 → 归约器与宿主测试红；
  - 外部结束一律记成用户结束、有了结束方式也不终结 → 宿主测试红；
  - 已结束的线程还接受推进 → 归约器测试红。

**评审后续（已修）**
- **残留的旧字段删干净**：
  - e2e 里五处线程样例还带着 `status: 'active'`；
  - 真机脚本 `live-guide-run.mjs` 还在打印旧的状态字段，现在打印结束方式。
- **过时注释与测试标题改成实话**：线程类型、宿主、后台、归约器、e2e 里「离开 active」「留在 active」「被放弃」「记成 completed」一类说法，以及两个测试标题。
- **「结束引导」的参数改为必填**：归约器那条路把线程自己的结束方式传进去，外部传它看到的那种。原来「进行中却没说明怎么结束就抛异常」的那一支不存在了。
- **只留一套词**：done 效果不再带另一套「来源」（model / backstop / fixed），直接带结束方式；后台按结束方式选择要说的话。
- **改名**：
  - Run record 的 `confirmed` 改为 `confirmation`，免得和步骤结果里的 `'confirmed'` 撞名；
  - `quota` 改为 `quota_exhausted`，与其余结束方式一样读作一件事，也对得上「配额用完」。
- **宿主测试补全**：T-2 到 T-5 也核对摘要里记下的结束方式和确认程度。现在九种结束方式中，每一种都有测试核对到摘要这一层。
- **e2e 核对后台四个外部结束入口各传哪一种**：关浮层、关标签页、在进行中的引导上再起一趟、点「结束引导」，这四段原有流程各自多了一条断言，核对摘要里记下的结束方式。另加一个 e2e 探针：把「关浮层」偷换成「用户结束」，看这条断言能不能抓到。
- **词汇表**：Run record 词条写全九种结束方式（归约器五种、外部四种）；Arrival 词条里那句过时的话改为「全部确认是 Run record 的确认程度，不是到了」。
- **设计文档**：run 的三值状态表换成两行；「只有 completed 才蒸馏」改为「只有确认程度为全部的那一趟才蒸馏、才可导出」。
