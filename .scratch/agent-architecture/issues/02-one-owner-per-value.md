# 02 — 同一个取值只有一个所有者

**What to build:**

被声明了两遍的取值收成一份，改一个取值只改一处。

- 四组取值（动作、完成依据、上一步结果、intent 名字）各只剩一份定义；给模型的回答形状、识别、校验都读这一份。
- `Place`（「同一个地方」，只看 origin + pathname）只剩一份实现，归约器与宿主的重新规划共用。
- Effect 的失败类型不再在归约器里重新声明。
- 线上协议里三个有意复制的类型（为防循环依赖，理由写在代码里）不动。

**实现记录**
- 四组取值由契约模块拥有：动作、完成依据、上一步结果、intent 名字。给模型的工具 schema 和校验器都从它读。
- Place 单独成一个以词条命名的模块，归约器、宿主的重新规划、尚未删除的 settle 模块都改用它。全仓只剩内容脚本算页面指纹时也拼了 origin 和 pathname，那是生成哈希，不是比较两个地方，保留不动。
- Effect 失败类型改从 Effect 的线上定义 import。
- 一致性测试不比较两个常量，而是从模型实际收到的 schema 读出「给了哪些值」，再逐个去问解析器和校验器「接受哪些值」。候选值两边都取：只取 schema 一边的话，schema 少写的值根本不会被拿去试，这正是验证时发现的漏洞。五种漂移改动（多给、少认、另写一份少一个）都会让它变红。

**评审后续（已修）**
- 失败类型原来还有第三份（运行循环里的同一组三个值），现已删除，改用 Effect 的线上定义；测试里的手写副本也改为引用这个类型。
- intent 名字和动作清单改由编译器守：契约导出 `Intent` 类型，并在编译期断言它和信封类型的 intent 双向相等；工具 schema 的工具名参数也改用这个类型。另有一个编译期检查：`UserAction` 里除 `observe` 外只要有一个没列进动作清单，就编译不过。四种临时改动都验证过会报错。
- 词汇表的 Place 词条已同步列出它现在的几种用途。
- 5 处过时注释已修正。校验器里的动作集合改名为 `STEP_ACTIONS`；它的报错文字没有改，因为修复轮时模型会读到这句话。
