# 07 — Fixed plan 自成一个模块

**What to build:**

检视器交来的计划，它的全部规矩住进自己的模块：开始、用过才前进、跳过就前进、走完即终结、页面变了只重画同一步、等待超时也不调用模型。归约器只负责分派到它。

**Blocked by:** 06 — 归约器的帮手成为独立模块，纯度守卫改成按依赖闭包算

**Status:** done

- [x] Fixed plan 现有的归约器用例一条不改，全部通过
- [x] 「永不调用模型」仍由发起模型调用的那道闸门结构性地保证，模块里写明这一点
- [x] 类型检查、单测、e2e、抽取器评测全绿，并且第 01 张冻结的快照逐字节一致

**实现记录**
- **Fixed plan 的规矩集中到一个模块**（宿主目录下的 fixed-plan），导出一个 `fixedPlan` 对象，装下它的全部规矩：
  - 开始：原样落下步骤，调用次数从 0 起、不再增加；
  - 等待超时：只有用过的一步才有窗口可关，关了就记「点了没到」并前进；
  - 页面变了：用过就前进，没用过就在当下的页面上重画同一步；
  - 跳过就前进；
  - 用过：只记下来，等页面回答；若页面已经先离开了点击发生的地方，那次离开就是回答；
  - 走完即终结：结束方式记为「步骤走完了」，结束语按是否全部确认来说。
  
  原来散在归约器各处的说明注释也一起搬了过来。
- **归约器只负责分派**：五个输入处理函数里只判断「是不是固定计划」，是就交给模块。所有线程共用的规矩仍留在归约器：页面是否真的变了、跨站后遇到凭据就停、页面变了能证明上一步已确认、判断到达期望。
- **「永不调用模型」仍由发起模型调用的那道闸门保证**：`tryEmitCallModel` 遇到固定计划直接拒绝；模块不 import 它，模块头注释写明了这一点。闸门处原来指向归约器函数的注释改为指向这个模块。
- **归约器现有用例一条没改**，全部通过。纯度守卫的依赖闭包自检加入了这个模块。
- **新增一条测试，直接钉住闸门**：现有用例都只从归约器入口测，闸门本身拒绝固定计划这件事没有测试直接守着。新测试直接调用发起模型调用的闸门，断言它对固定计划不发调用、不计数、不留在途记录。现有用例一条没改。
- **变异探针全部变红**（改完即恢复，文件哈希核对一致）：
  - 页面变了没用过也前进、等待超时没用过也前进、跳过不前进、用过就立刻前进、走完不终结；
  - 闸门不再拒绝固定计划（由新测试抓到）；
  - 归约器忘了把等待超时分派给固定计划。
- **验证**：类型检查 0 错；单测 34 个文件 1649 条全绿；e2e 187/187；抽取器评测全部门槛通过；两份快照哈希不变。归约器从 638 行减到 537 行。

**评审后续（已修）**
- **「记下一次换页」只剩一处**：抽成共用函数 `recordMove`，负责换表、清掉跨站标记、把上一步记为已确认、判断到达期望，模型那条路和固定计划「用过的一步前进」都调用它。固定计划的换页处理改为只收新的页面表：没用过就不再先算好一份记录再丢掉。行为不变，现有用例一条没改。
- **「永不调用模型」只在两处说**：模块头和闸门。
  - 等待超时那段原来说「忘了区分会真花钱」，与模块头矛盾；改为实情——忘了分派，这一步会被闸门拒绝、卡住不前进，但花不了钱。
  - 开始那段改为指向闸门。
  - 线程类型里「由归约器的唯一分派入口保证」改为指向 `tryEmitCallModel`。
- **「断点」按词汇表用**：它指引导停下来重看页面的那个时刻，代码里的处理位置改叫「输入处理」。「用过」里那段行内注释改为点明是 `replan.ts` 的换页流水线先提交了这次换页，不再说「重新规划」。
- **模块头补全**：写明到达检查也在 `recordMove` 里，与模型那条路共用。
- **评审后续的验证**：类型检查 0 错；单测 34 个文件 1649 条全绿；e2e 187/187；抽取器评测全部门槛通过；两份快照哈希不变。9 个变异探针全红：原来的 7 个，加上「记下换页时不记已确认」和「没用过的一步也记下换页」——后者被现有用例抓到，说明「没用过就不记已确认」本来就有测试守着，不必另补。
