# 08 — 真机报告页：统计量、你的判定存进页面数据库、再拉回仓库

**What to build:**

每一轮生成一张报告页，形式延续第四到第七轮（第七轮：https://claude.ai/code/artifact/8d250e9f-f6c0-4356-b88e-3e06452d930f）。和以前不同的有两处：页上的数全部来自打分脚本；判定不再存在你这台浏览器的本地存储里。

- **生成**：一个脚本读这一轮的结果文件（有上一轮就连上一轮的一起读），用第 02 张的函数计算，把算好的数据嵌进页面。页面自己不再算任何数。
- **报告什么**（只报告，不设门槛）：
  - Arrival 率：按目标聚类，附 Wilson 区间；分站点再列一次；本轮能分辨的最小差距。
  - pass^1、pass^2、pass^3。
  - 与上一轮按目标配对的差、配对 SE 与 95% 区间。只在两轮共有的目标上配对，写明共有几个。
  - 跳数、调用数、token（含缓存命中）、成本。成本按模型配置里的单价算；没给单价就只报 token。
  - 安全违规：
    - 终点对，但最后一步唯一地指错（L-4，即你判了「最后一步指错」的趟）；
    - 指向 Sensitive 控件的步；
    - 以「跨站凭据停止」结束的趟。
  - 程序化判据与你的判定的一致率、precision、recall（判定拉回来之后才有）。
  - 每一趟一行：终点 URL；停下时屏幕上还指着什么；按 URL 分的「停在目标 / 踩到过又走开 / 从没到过」；结束方式与确认程度；最后一帧截图。
- **判定**：每一趟四个选项：
  - ✓；
  - ✗ 终点错；
  - ✗ 最后一步指错；
  - 不作数：验证码、站点故障这类不是产品的问题（Online-Mind2Web 的标签 2）。不作数的趟不进 Arrival 的分母，页上写明有几趟。

  判定存进页面自己的数据库，一趟一条。
- **拉回仓库**：用 Artifact 工具的 `read_db`，把这一轮的判定拉进轮次目录，成为判定文件。打分读它：正式的 Arrival 用你的判定，程序化判定只用来对账。拉回之后重新生成、重新发布同一张页，补上对账那一节。
- 报告页由 agent 用 Artifact 工具发布，声明 `db` 能力；截图随页面一起发布。

**Blocked by:** 02 — 统计的纯函数，先复现第六、七轮的数；06 — 程序化判据：终点 URL 加最后一步，并能和你的判定对账

## 实现记录（2026-09-14）

- `evals/task/results.ts`：一趟的结果由日志里这一趟的行和它的调用行算出（`resultOf`），harness 与 `rebuild-results.mjs` 共用。比原来多三样：每跳之后的地址 `visited`、指向敏感控件的回答数 `sensitivePointed`（用产品自己的解析器读回答，引用的取法与判定评估的 `pointedAt` 是同一个函数）、最后一帧 `shot`。`t06-a/results.json` 已从原始日志重建。
- `evals/task/report-data.ts`：页上所有的数都在这里算，配 `tests/unit/report-data.spec.ts`。你有判定时正式分用你的判定（不作数的不进分母），没有时暂用程序化判据，页上写明用的是哪个；配对只在两轮都判完时才用你的判定，否则两边都用程序化判据。
- `evals/task/report.mjs <轮次> [--previous <轮次>]`：写出 `runs/<轮次>/report-data.json`（打分输出，入库）和 `runs/<轮次>/raw/report/`（页面与转成 JPEG 的最后一帧），打印发布用的 `files`。页面只读写 `verdicts/<P遍-目标>` 的 `{verdict}`，不算任何数。
- 拉回：`read_db`，`collection: verdicts`，`out_dir: evals/task/runs/<轮次>`，落成 `runs/<轮次>/verdicts/<P遍-目标>.json`；再跑 `report.mjs`，用同一路径重新发布。
