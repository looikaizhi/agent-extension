# 05 — harness 不再替产品制造失败：跨站确认卡，与串轮的账号状态

**What to build:**

harness 有两处空白，都会把产品没犯错的趟记成失败。

- **跨站确认卡**（规格 A 第 14 张留给规格 B 的事）：
  - 冒烟那一轮的第 6 趟，模型第一次从 n8n-docs 仓库页指向站外的 `docs.n8n.io`。产品按设计先弹出跨站确认，线程停在「待确认跨站」。
  - harness 只会点高亮，等了 15 秒没看到高亮框，就替用户结束了这一趟。凡是需要离开本站的目标，今天都会停在这里。
  - 改成：线程停在「待确认跨站」时，harness 像用户那样在侧栏的卡片上点「继续」，然后照常往下走。日志记下卡片出现在哪一跳、从哪个站去哪个站、harness 怎么答的。
- **串轮的账号状态**：
  - 第七轮 P2-4 回车时，选中的是「最近搜索」里上一趟留下的 n8n-io/n8n-docs，整趟因此走偏。
  - 改成：每一趟开始前，清掉目标站点上会跨趟保留的状态，同时保持 github.com 的登录。先查清 github 的「最近搜索」存在哪里（浏览器存储还是账号里），再决定怎么清。
  - gitee.com 与 help.aliyun.com 不登录，每趟之前同样清一次。

**实现记录**
- **先量了「最近搜索」存在哪里**（一次性探针 `tests/spike/probe-recent-search.mjs`，不装扩展、不调模型）：
  - github 把它存在 localStorage 的 `github-search-history` 里。搜过一次之后，下拉第一项就是「n8n-io/n8n-docs · Recent search」；
  - 只清 localStorage 与 sessionStorage，它就没了，登录名仍在（登录靠 cookie）；
  - 再用 CDP 清掉除 cookie 以外的全部存储，结果相同。
- **每一趟开始前清站点状态**（`clearSiteState()`）：先切到空白页，免得还开着的页面把状态写回去；再用 CDP 的 `Storage.clearDataForOrigin` 清掉目标站点除 cookie 以外的全部存储。按起始页的 origin 清，gitee.com 与 help.aliyun.com 同样适用。
- **开局那一行记下登录名**：匿名跑的趟以后能认出来，报告可以单列。
- **跨站确认卡**（`answerCrossSite()`）：每一跳开始时，线程若停在「待确认跨站」，harness 就在侧栏的卡片上点「继续，带我去」，然后照常点那一步。
  - 点的是侧栏里真实的按钮，但用派发 click 事件，不用 Playwright 的普通点击：普通点击会把侧栏页切到前台，而侧栏跟着活动标签页走，卡片就会替侧栏自己的标签页作答。真实的侧栏在页面旁边，不会取代它。
  - 日志的趟那一行加 `crossSite`：出现在哪一跳、从哪个站去哪个站、答上没有。10 秒内卡片没出现，或者点了之后线程仍停在待确认，就记成这一跳走不动，停下。
