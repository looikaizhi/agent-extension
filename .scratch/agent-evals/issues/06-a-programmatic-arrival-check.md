**What to build:**

今天「到了没有」只按终点 URL 的正则判。你的口径是终点 URL 对，**并且**停下时屏幕上的最后一步指对了（CONTEXT.md `Arrival`）。把这个口径落成数据和函数：

- **目标写成数据**，放在 `evals/task/`：id、站点、起始页、目标原文、Sighting goal 还是 Acting goal、程序化判据。
- **程序化判据** = 可接受的终点 URL（一组模式）× 可接受的最后一步。最后一步可以是：
  - 一组 Descriptor 模式（role 加 name）；
  - 「以 done 收尾，屏幕上没有高亮」。

  两半都中才算到。
- **harness 每一趟结束时记下**：
  - 终点 URL；
  - 最后一步：屏幕上还指着的那一步的 Descriptor 与动作；或者以 done 收尾；或者停在跨站确认卡上，这时记下指向站外的那一步；
  - 程序化 Arrival，以及没中的是哪一半。
- **每一轮写一份结果文件**，放在轮次目录里，进版本管理。一趟一条：目标、第几遍、终点 URL、最后一步、程序化判定、跳数、调用数、token、Run record 的结束方式与确认程度。之后的报告、配对、语料都读它，不再回头读原始日志。
- **两个纯函数**：
  - 判定：给终点 URL、最后一步、判据，得出到或没到；没到时说清是 URL 错，还是最后一步错。
  - 对账：给程序化判定和人工判定两份，算一致率、precision、recall，以人工为准。人工标了「不作数」的趟不计。
- 今天 7 个 github 目标的 URL 正则改写成新判据（补上最后一步），正则删掉。

**实现记录**
- **判据比票面写得细**：不是「一组终点 × 一组最后一步」，而是几组「终点 + 这个终点上可接受的最后一步」，任意一组两半都中才算到。
  - 为什么：「带我去看 n8n 的官方文档站」，停在 `docs.n8n.io` 并以 done 收尾算到；停在 n8n-docs 仓库页、最后一步指着 `docs.n8n.io` 那个链接也算到。可两个集合做积，还会把「n8n-docs 仓库页 + done」也算成到，你没这样判过。
  - 没到时：一组终点都没中，报「终点不对」；终点中了而那一组的最后一步都没中，报「最后一步不对」。
- **屏幕上的最后一步有三种**（`evals/task/arrival.ts`）：
  - done：模型说到了，屏幕上没有高亮；
  - 一个步骤：还高亮着的那一步，或者在跨站确认卡后面等着的那一步（另记 `behindCrossSiteCard`），记下 Descriptor 的 role、name 与动作；
  - 无：以别的方式结束，屏幕上没有高亮，并写明原因（例如打转兜底）。
  - 取法：harness 结束这一趟之前线程还在，就取它当下的那一步；线程已经没了，就看 Run record，模型说到了是 done，其余都是无。
- **人工判定的四种**：到了、终点错、最后一步指错、不作数，对应第 08 张页面上的四个按钮。对账以人工为准，不作数的趟不计，分母为 0 时给 `null`（未测）。
- **目标写成数据**（`evals/task/goals.ts`）：id、站点、起始页、目标原文、Sighting 还是 Acting、判据。每条判据的依据写在注释里。第六轮你判过的几种写进了测试，所以以后定稿时改出和它们冲突的判据会变红（探针 A8 证明了这一点）。
- **草稿里要你在第 07 张拍板的几处**：
  - `gh-repo-address`（Acting）：done 也算。模型通常在用户点了复制之后才说 done，但判据看不出 done 之前是否真的点过；
  - `gh-releases`、`gh-contributing`：停在仓库首页、以 done 收尾，草稿不算；
  - `gh-docs-site`：停在 n8n-docs 仓库页、以 done 收尾，草稿不算，只有最后一步指着 `docs.n8n.io` 才算；
  - `gh-ci`：停在 workflows 目录页、以 done 收尾，草稿算。
- **harness**：
  - 目标改从 `goals.ts` 读，`--site` 按目标的 `site` 字段选；URL 正则与 `judgeArrival` 删掉；
  - 每一趟的日志行多了终点 URL、最后一步、程序化判定，以及这一趟的调用次数和 token，终端也逐趟打印判定；
  - **结果文件** `evals/task/runs/<id>/results.json`（进版本管理）：轮次的元信息（与日志第一行相同），加上每一趟的目标、第几遍、终点 URL、最后一步、程序化判定、跳数、调用数、请求数、token、Run record 的结束方式与确认程度、跨站卡与仪器故障（有的话）。每跑完一趟就整份重写，跑到一半中断也不丢已经跑完的趟。
- **`score-run.mjs`**：`task_success_rate` 读的 `arrived` 现在是程序化判据（终点和最后一步两半），标签跟着改了。
