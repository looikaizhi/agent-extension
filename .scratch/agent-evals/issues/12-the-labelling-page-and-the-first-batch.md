## 实现记录（2026-09-15，工具部分）

- **挑法**（`evals/decision/select.ts`，纯函数）：
  - 候选只取能按当前代码逐字节重拼的状态。
  - 三个站点平分名额，某个站点不够时，它剩下的名额让给别的站点。
  - 站点内按「在一趟里的位置（开局、中途、临近终点）× 当时回答的意图」分组，轮流每组取一个，所以少见的回答（done、clarify、need_docs）一定挑得到。
  - 组内按状态 id 的哈希排序来取：顺序固定，也不看状态的内容。
- **命令**：
  - `evals/decision/batch.mjs <轮次> [--size 60]`：挑出第一批，写进 `evals/decision/batch-1.ndjson`（进版本管理）。
  - `evals/decision/label.mjs`：生成标注页，写到 `evals/decision/raw/label/index.html`（不进版本管理），发布时声明 `db`。
  - `evals/decision/pull-annotations.mjs <read_db 的目录>`：把拉回来的文档转成 `evals/decision/annotations.json`。
- **标注页**：
  - 每个状态显示目标、走过的步骤与路线、模型当时的回答、四个意图按钮，以及可过滤的元素表：勾选可接受的元素，再为每个勾上的元素选动作。
  - 敏感项不能勾；标出「模型当时选」与「建议」。
  - 页面数据库里每个状态一个文档，放在 `annotations/<状态 id，把 / 换成 ~>`，内容是 `{state, intent, acceptable}`。
  - 预填：只对你判了「到了」的那趟里的状态，把模型当时的意图和第一步作为建议，你点「采纳建议」才算数。
- **拉回时的核对**（`evals/decision/annotations.ts`）：以下任一情况都会让整批不写：意图不认识、动作不认识、一步没有动作、ref 不在这个状态的元素表里、ref 是敏感控件、意图是 guide 却一步没勾、状态不在这批语料里。
