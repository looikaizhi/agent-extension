# 13 — `npm run eval:decision`：重放、打分、报告

**What to build:**

改完提示词、换了模型或加了 Plugin，跑这一条命令，就知道模型每一跳的选择有没有变差，不必先花一轮真机。

- **做什么**：读语料与标注。对每个状态，按这次指定的 Plugin 组合拼出 Context，用引导 agent 的门面和运行循环、真实的 Provider 答一次；每个状态答 k 遍（默认 3）；用第 10 张的函数打分。
- **参数**：Plugin 组合与模型配置（写法与 `eval:task` 相同）、遍数、状态子集。
- **报告**：
  - 意图准确率、第一步准确率，附区间；
  - 解析失败率、校验失败率；
  - 指向表外或敏感控件的次数；
  - 每个状态的 pass^k：稳定对、稳定错、时对时错各有几个；
  - token（含缓存命中）、成本、每次调用的延迟（中位数与 p90）。
- **结果文件**进版本管理，记下 Plugin 组合、模型、快照指纹、时间、语料与标注的指纹，以及每个状态每一遍的回答原文，方便以后复查。
- 网络错单独计，不算模型答错。并发设上限，撞上限流就退避。
- 手动运行，不进 `verify`。先只覆盖引导 agent。

**Blocked by:** 02 — 统计的纯函数，先复现第六、七轮的数；10 — 离线打分的纯函数，与标注的格式；11 — 离线语料：从真机日志抽出状态，并证明能逐字节重放；12 — 标注页，与第一批 50–80 个状态

## 实现记录（2026-09-14）

- **位置**：
  - `evals/decision/replay.ts`：一个状态按指定的 Plugin 组合重拼 Context，用引导的运行循环和真实的 Provider 答一次；
  - `evals/decision/report.ts`：报告的纯函数；
  - `evals/decision/run.mjs`：命令行，即 `npm run eval:decision`；
  - `evals/options.ts`：和 `eval:task` 共用的参数（Plugin、端点与模型、单价、轮次 id、`.env.local`、成本公式），harness 也改用它；
  - 测试在 `tests/unit/decision-replay.spec.ts`、`tests/unit/eval-options.spec.ts`。
- **标注可选**（改了第 10 张的 `score.ts`）：没有标注的状态照样计入解析失败、校验失败、指向表外或敏感控件，对错记为 `null`；准确率、pass^k、稳定性只在有标注的状态上算。标注在花钱之前先对着各自的元素表核对一遍。
- **语料两种来源**：`--from <真机轮次>` 直接从日志里取全部状态；`--corpus <文件>` 读 `extract.mjs --out` 写的文件（第 12 张的第一批会是这个）。逐字节核对不拦重放：量的就是改了之后的代码，指纹不同只提示。
- **网络错**：429、5xx、断网，退避重试 4 次（等 1、2、4、8 秒）；仍失败的记为网络错，单独计，不进任何比率。Key 被拒这类不可重试的不再问。并发默认 4。
- **结果文件**：`evals/decision/runs/<轮次>/results.json`，进版本管理，已存在的不覆盖。记下 Plugin 组合、模型与单价、当前快照指纹、语料的来源、指纹与哈希、标注文件与哈希、报告，以及每个状态每一遍的回答原文、工具名、失败、用量、耗时、尝试次数。报告只从回答算，所以有了新标注可以不再问模型就重打分。
