# 02 — 统计的纯函数，先复现第六、七轮的数

**What to build:**

两层评估共用一组统计函数，放在 `evals/` 根下，零 I/O，不依赖产品代码。输入统一成「每个簇跑了 n 遍、成功 c 遍」：Task eval 里一个簇是一个目标，Decision eval 里一个簇是一个状态。公式与出处都在 `docs/research-agent-evaluation-metrics.md` 第 4 节。

- **Wilson 区间**：二值结果、小样本。
- **按簇聚类的成功率与标准误**：同一个簇的几遍不独立，先对每个簇求均值，再在簇均值上算 SE（Miller §3.1）。
- **聚类的 Wilson 区间**：照 Inspect `ci_wilson` 的做法，用 Korn–Graubard 有效样本量 p(1−p)/v̂（上限为总遍数）代替 n。v̂ 取上一条聚类 SE 的平方。
- **pass^k**：对每个簇算 C(c,k)/C(n,k)，再对簇取均值。pass@k 也算，只用来诊断能力上限。
- **两个版本按簇配对的差**：差的均值、配对 SE（式 7）、95% 区间。只在两边都有的簇上配对，并报出配对了几个。
- **最小可检出差距**：由配对 SE 反解（式 10），α=0.05、功效 80%。同时报 z 与 t（自由度 = 簇数 − 1）两个数；只有 7 个簇时，两者差得不小。

区间的临界值统一用 z=1.96。研究报告第 5.6 节的配对区间就是这样算的，t 只出现在最小可检出差距那一处。

测试数据是第六、七轮每个目标的成功次数（按 URL 口径的 `arrived`）：从两份日志里数一次，写进测试并注明出处，不用被测的函数去生成。

**实现记录**
- **位置**：函数在 `evals/stats.ts`；测试在 `tests/unit/stats.spec.ts`，和其余单测一样随 `npm test` 跑，不花钱。
- **八个导出**：`wilson`、`clusterRate`、`clusteredWilson`、`passHatK`、`passAtK`、`pairedDiff`、`minDetectable`、`tQuantile`。输入统一是 `{id, n, c}`；配对按 `id` 认簇。
- **测试数据**：第六轮各目标 3 遍里到了 2、3、0、2、1、0、3 遍（共 11/21），第七轮 2、2、0、2、1、0、1（共 8/21）。按 URL 口径的 `arrived` 从两份日志各数一次，写进测试，没用被测函数生成。
- **聚类 Wilson**：用 Korn–Graubard 有效样本量 p(1−p)/v̂，v̂ 取目标均值 SE 的平方，上限为总遍数。临界值是 z，这一点与 Inspect 不同（Inspect 用自由度为簇数 − 1 的 t）。
  - 核对值手算写在测试里：第六轮有效样本量 660/68≈9.71，区间 25.1%–78.3%；第七轮 624/34≈18.35，区间 19.8%–60.5%。
  - 另用 python 独立复算，不经过这份代码，结果一致。
- **t 分位数自己算**：Lanczos 的 lnΓ、不完全 Beta 的连分式、二分求逆。仓库里没有统计库，为一个分位数引依赖不划算。按 t 分布表核对了 6 个值：自由度 1、6、30 下的 0.975 分位，自由度 6 与极大自由度下的 0.8 分位，以及对称的 0.025 分位。
- **边界取值**（都写在函数注释里，各有测试）：
  - 0 次成功时下界恰为 0，全部成功时上界恰为 1。第一版在 10/10 上算出 0.9999999999999999，现在端点直接取精确值；
  - 簇均值之间没有差别（全没到、全到了）：有效样本量退回总遍数；
  - 簇之间比独立试验还整齐：有效样本量封顶在总遍数。这条一开始没有测试守着，第六、七轮的有效样本量都小于 21，去掉上限也全绿。补了一个构造样本（按公式 27，封顶在 12）；
  - 只有一个簇：SE、聚类区间、配对 SE、t 版可检出差距都是 `null`，不报 0；
  - 跑了不到 k 遍的簇不进 pass^k，单独计为 `skipped`；一个够 k 遍的都没有时 `value` 为 `null`；
  - 两边没有共同的簇：配对为 `null`；只有一边有的簇不配对，计为 `onlyA` / `onlyB`；
  - 不合法的次数（c > n、n < 1、非整数、重复 id、空列表、k < 1）直接抛错。
- **守卫**：架构守卫新增一条，`evals/stats.ts` 零 import，因此零 I/O、不依赖产品代码。
