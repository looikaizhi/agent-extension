# 03 — harness 有了 main 函数：跑什么、用什么跑，都写在日志第一行

**What to build:**

harness 今天是一段从上往下执行的脚本，目标、遍数、模型要么写死，要么靠环境变量。改成一个 main 函数，每次评估由参数决定：

- **参数**：
  - 目标子集：按站点或目标 id 选；
  - 遍数；
  - Plugin 组合：已登记 Plugin 的名字列表，`none` 表示全关；
  - 模型配置：端点、模型名、单价（输入、缓存命中的输入、输出，按每百万 token）。密钥仍从 `.env.local` 读；
  - 轮次 id：不给就按开始时间生成。
- **跑之前把 Plugin 组合写进产品设置**：每一个已登记的 Plugin 都显式写开或关，不靠默认值。开关在一趟开始时读一次（decisions.md「Plugin 开关按趟生效」），所以在第一趟之前写好就够了。
- **日志第一行**：Plugin 组合、模型配置（不含密钥）、快照指纹、目标集、遍数、开始时间。
- **快照指纹**用当前代码现算：引导 agent 的 system 消息、工具 schema，加上在 `evals/` 自带的一份固定输入上拼出的 user 消息（包裹标记用固定值），取哈希。不读快照文件，也不依赖 `tests/`。第 13 张的 Decision eval 用同一个函数。
- **每一轮一个目录** `evals/task/runs/<轮次 id>/`：
  - 原始日志、截图、录像放在它下面的 `raw/`，不进版本管理；
  - 之后几张票加的结果文件、判定文件放在轮次目录本身，进版本管理；
  - 不清空、不覆盖别的轮次。规格 A 第 14 张冒烟时，默认日志被那一轮覆盖、默认截图目录被清空，只能靠开跑前手工另存。
- **自检**：每一趟结束后读 Run record。它记下的 Plugin 组合必须等于这次指定的组合；对不上就把这一趟标成仪器故障，不当作对模型的观测。

目标集仍是今天的 7 个，只是可以选子集。环境变量 `PG_ROUNDS`、`PG_REPEATS`、`PG_SHOTS` 由参数取代，删掉。

**实现记录**
- **main 函数**：`evals/task/live-github-run.mjs` 导出 `main({ run, goals, passes, plugins, model })`。命令行参数由 node 自带的 `parseArgs` 读成它的参数，读不懂的在打开浏览器之前就报错退出。`PG_ROUNDS`、`PG_REPEATS`、`PG_SHOTS` 删掉。
  - 浏览器句柄留在模块层，由 `main` 里的 `launch()` 打开，各帮手函数一行没改。理由写在注释里：一个 harness 进程从头到尾只开一个浏览器，把六个句柄穿过每个帮手，只会让每一行都变而什么也没得到。
  - 每一趟抽成 `trip()`。原来的循环体本来就缩进两格，正好成为函数体。
  - 七个目标加上 id（`gh-repo-address` … `gh-ci`）。`--goals` 按 id 选，`--site` 按起始页的域名选。
  - 默认值：全部目标、3 遍、产品默认开着的 Plugin（今天是 `skill`）、`.env.local` 里的端点与模型、按开始时间生成的轮次 id。单价 `--price 输入,缓存命中的输入,输出`（每百万 token）可以不给。
  - 目标集里有 github.com 的目标才登录。
- **Plugin 组合写进设置**：每一个已登记的 Plugin 都显式写开或关。
- **日志第一行**：`kind: 'header'`，含轮次 id、开始时间、目标集、遍数、Plugin 组合、模型配置（端点、模型、单价，没有密钥）、快照指纹。`score-run.mjs` 本来就只读带 `phase` 或 `pass` 的行，会跳过这一行，不用改。
- **快照指纹**（`evals/fingerprint.ts`）：真实的运行循环，配一个只做记录的假 `complete`，包裹标记固定。
  - 固定输入：一页 github 仓库页的四个控件、一步已确认的历史、一段路标、一个新出现的 ref，以及每个已登记 Plugin 的段落。取 sha256 的前 16 位。
  - 运行循环发出的请求不是恰好一次（出了修复轮）就报错，免得把修复请求也算进指纹。
  - 它只覆盖引导 agent。改问答信封说明里的字，指纹不变，见下面的探针。
- **node 要用 `--experimental-transform-types`**：指纹经运行循环加载了 `provider.ts`，那里的错误类用了 TS 的构造参数属性，strip-only 模式不认。`eval:task` 改用 transform 模式。第 13 张在 node 里调真实的运行循环时，也会碰到同一个类。
- **轮次目录**：`evals/task/runs/<id>/raw/` 放 `log.ndjson`、截图和录像；轮次 id 已经存在就拒绝起跑。`.gitignore` 里第 01 张留下的两行临时规则，换成 `evals/task/runs/*/raw/`。第 01 张冒烟时留在 `evals/task/` 下的日志与截图，挪进了会话 scratchpad。
- **结束一趟统一走 `endTrip()`**：
  - 先发 `END_GUIDE`，再读这一趟的 Run record：同一个目标、写于这一趟开始之后，最多等 5 秒；
  - 核对 Plugin 组合，对不上或找不到，就标上 `instrumentFailure`，汇总里单独计数；
  - 以前只有线程自己结束的趟才读 Run record，harness 替用户结束的那些没有；现在每一趟都读，日志里每一趟都有 `record`（含 `plugins`）。
