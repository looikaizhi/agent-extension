# 04 — 让两次评测仍然可比

**What to build:**

**这一票救的是一条会「绿着坏掉」的链**，而且必须趁旧路径还活着、还有参照系的时候做。切换之后再做，就没有可回头的基准了。

**第一件：指纹。**

评测的指纹把「发给模型的东西」整个序列化后取哈希，它的文件头写着：*Two results are directly comparable only when this matches; when it does not, part of the difference between them is the prompt.*

靶子一换成中立形状，**哈希必变，而线上字节没变**。于是每一次评测都会打印「发给模型的东西不同，这正是要量的差别」——**一句假话**；语料会被警告不可重拼；所有历史 run 的指纹永久失去与今后任何一次 run 的可比性。

改成**只哈希 `{system, user, tools}` 三段渲染文本**。它本来就只想回答「发给模型的东西变没变」，而那三段是协议无关的——这么改之后，以后再加协议它不会再动。代价是一次性重录基准。

**第二件：Trace 与 Decision 语料。**

运行循环把第一条消息的内容当 `system` 字符串存进 Trace；语料从 Trace 的 `system` / `tools` 造出「模型当时读到的东西」，回比时用的是字符串比对和工具 schema 的序列化。content-parts 数组加上扁平的 `ToolSpec` 一来，**已提交的一百多条语料永久对不上**。

最坏的是它**不会红**：语料抽取用「有差异就跳过」来过滤，会静默产出零条；而语料的单测自产自销，两边一起变。词汇表里 `Decision eval` 那句「与模型当时读到的一字不差」会在这一刻变成一句无法再验证的话。

**决定：Trace 的 `system` 与 `tools` 保持为渲染后的字符串**，不跟着中立类型变成结构化对象。Trace 的受众是人和语料，不是协议。
