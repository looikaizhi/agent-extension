# 05 — 运行循环改说中立话，旧路径删除

**What to build:**

契约收口。工具循环、修复轮、侧栏的实时草稿全部走中立类型，`complete()` 连同它的 OpenAI 知识删除。

**这一票不拆。** 不是范式上的讲究，是具体的：delta 的类型一改，运行循环的聚合、侧栏的草稿分叉、指纹里的录音桩、以及一批测试里所有的假 `complete` 会在**同一次类型检查里一起红**。类型系统不给你「新路径已通、旧路径待删」的绿色中间态，除非同时养两套 delta 类型和两条循环分支——那正是「不保留向后兼容」禁止的东西。硬拆只能拆出一个要靠类型断言才编译得过的中间态，比不绿更坏。

**四件事一起落：**

1. 运行循环消费判别联合的 `ModelDelta`，那套「第一片带元数据」的聚合逻辑随之简化
2. 侧栏的实时草稿分叉改认 `tool-input-delta`——**它的性质原样保住**：仍然是包一层高阶函数，运行循环仍然不知道有面板存在
3. 旧的 `complete()` 与 OpenAI 的线上形状从运行循环这一侧彻底删除
4. 模型输入快照的靶子翻成中立 `ModelRequest`；02 那条请求体全等证明在本票内删掉

**要改结构的测试**（不是「只改类型」）：运行循环、工具循环、effect、语料重放、语料本身、模型输入快照——它们手写的假 delta 是扁平字面量，判别联合一来全部要重写。

**零改动的**：配额、一次一步、路线与步骤这几个文件根本不碰运行循环，测的是归约器。
