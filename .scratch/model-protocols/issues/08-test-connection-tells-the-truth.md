# 08 — 「测试连接」说真话

**What to build:**

用户按下「测试连接」，测的是**这个端点能不能真的驱动这个产品**，而不只是「Key 没被拒」。

这是本规格唯一有真正用户可见新行为的一票。

**一、两段探测。**

1. **取模型列表**（保留）——便宜、不花 token，而且 401 无歧义。现有注释说得很准：这里的 401 是「Key 错了」，不会被误读成「模型说了什么」。
2. **一次最小的真调用**（新增）——一个玩具函数加上「必须调用工具」，看回来的是不是工具调用。

三种读数，三种说法，并**写回 06 的三态开关**：

| 读数 | 开关 | 对用户说 |
|---|---|---|
| 回来是工具调用 | 支持 | 可用 |
| 回来是文字、工具调用为空 | 不支持 | 这个端点静默忽略了「必须调用工具」，跑不动本产品 |
| HTTP 400 | 留在未知 | 把端点的报错原样给他看（多半是 schema 关键字被拒） |

代价是一次几十 token 的调用，换来的是**把静默降级提前到他按下按钮的那一刻**，而不是等他在引导跑到一半时撞上。这也是唯一能回答「Gemini 认不认强制工具调用」的机制——而且是用户自己按一下就有答案。

**二、设置页那一行标注。** 每条端点标出「原生 / 兼容层」，兼容层明说哪几样用不上（例如没有提示词缓存、成本面板看不到缓存数字）。**只是一行字，不做能力矩阵界面。** 内容来自上面的探测结果，不是写死的表。

**三、OpenAI preset 改成新一代机型。** 协议选 `openai-responses`，模型名换成现行的 `gpt-6-*`。这是 00 那张票里唯一留下来没改的一条，因为它必须等 07。

**四、e2e 的打桩跟着改。** 冒烟测试对 OpenAI 的 Chat Completions 地址打了桩并断言 0 次请求，注释写明它的作用是「如果这道闸将来被意外削弱、又开始发请求了，桩会把它挡在 CI 的真实网络之外」。preset 一改成 Responses，真正会被打到的是另一个地址——**这个桩不再拦任何东西，而断言照样绿**，漏出去的请求直奔真实 OpenAI。一条安全网会静默变成一句空话。

## ⚠️ 一处有意的偏离：那一行字说的不是「原生 / 兼容层」

票面要的是「每条端点标出原生 / 兼容层」，而且明说**不能是写死的表**，内容要来自探测结果。这两条凑不到一起：

- 「原生 vs 兼容层」是**血统**，一次探测观测不到。能看出血统的只有「这个域名是不是这家厂商自己的」，那正是一张写死的表。
- 想用能力反推也不行：最直接的信号是「协议声明支持提示词缓存，而这个端点没报缓存数字」，但探测调用的提示词只有几十个 token，本来就命不中缓存——连 OpenAI 自己都会被判成兼容层。

所以这一行报的是**实测到的那一件事**：这个端点认不认「必须调用工具」，以及认不出来时那意味着什么。它永远不会说一句没量过的话。
真要「原生 / 兼容层」那个标签，得先决定它的来源——一张按域名写死的表，或者别的信号。那是你的决定，不是我该替你写死的。
