# 03 — 嵌入框架里的东西

**What to build:**

内容脚本 `allFrames: false`（[content.ts:25](../../../src/entrypoints/content.ts)），抽取器遇到 `iframe`/`frame` 直接跳过（[extract.ts:358](../../../src/core/extractor/extract.ts)）。真实站点里嵌入式控制台、结账组件、文档阅读器、登录与客服窗口都是 iframe。

后果不是报错，**是静默**：那些控件根本不在元素表里，模型只会以为「这一页没有」，然后指别处或者反过来问用户。CONTEXT.md 里也没有一个字说明这条边界。

**Blocked by:** 02

**Status:** 两层都 done —— 第一层 2026-09-22，第二层 2026-09-27

## 分两层，先有可用的那一层

**第一层——看得见、说得出。** 顶层抽取时数一数：这一页有几个**装着可交互内容的**框架，它们在哪。元素表把这件事如实带给模型，模型就能说「你要的那块在一个嵌入框架里，我现在看不到」，而不是编一个不存在的入口。这一层不需要动 `allFrames`，不动 ref 的命名空间，不动高亮路由——它只是把一个已知的盲区从「静默」变成「明说」。

**第二层——真的进去。** `allFrames: true`，每个框架各有一份内容脚本；宿主要把多份元素表合成一张（ref 要带框架身份）、要把 HIGHLIGHT 路由到正确的那一份、浮层要画在正确的坐标系里。这是真正的工作量，单独评估，不和第一层挤在一张票里。

## 进度记录（2026-09-22）

- **抽取器里那行注释是假的**：「Frames are a separate document; the frame protocol handles them」——那个协议不存在，`allFrames: false`，框架就这么被静静丢掉了。
- **做法**：walk 遇到 iframe/frame 收集起来（不走进去），过滤成「看得见且至少 120×60」，按面积取前 5，读出 `title`/`name`/`aria-label` 和 src 的域名，作为 `FrameNote` 挂在 `LocatorView`/`PromptTable` 上，再由 `toPromptText` 写成表头的一行 `frames …`。
- **`PromptTable.frames` 是可选的**：「这张表没提框架」是一种合法状态（手写的夹具、更早录下的语料），而唯一的真实生产者 `project()` 总会填。
- **代价是一次金语料重采**：`MARK_GUIDE` 多了描述这一行的那一段，于是「逐字快照」和「金语料漂移」两处按设计红了。照仓库既有的路子重跑了 `guide-envelope-smoke.mjs` 并用 `build-golden.mjs` 重建夹具（19 次真实调用），头部补了这次重采的说明。

## 第二层做完了（2026-09-27）

### 怎么进去：按需，不加权限

静态注册仍然 `allFrames: false`。`enterFrames()`（`shared/rpc.ts`）先用**已有的 `scripting` 权限**往每个框架注一段一次性探针（只读地址、视口尺寸、控件个数，装不下任何东西），挑出「大到装得下东西、且真有控件」的最多 5 个，再把内容脚本只装进这几个。

- 不需要 `webNavigation`——那会多一条安装警告，而这个仓库对权限的克制是写在 manifest 注释里的。
- 广告与跟踪框架既不被装内容脚本，也不进元素表。
- **已经在答话的框架不重装**：重复注入会触发 `content.ts` 的 SHUTDOWN 交接，把那个文档的浮层一起拆掉——那样每跳都会把刚画在框架里的框抹掉。

### 合表：`core/extractor/merge.ts`

顶层 + 各框架各自投影，宿主合成一张。refs 天然不撞车（`makeRef` 写的是 `f3e12`）。表的身份仍然是顶层那一页的；每一份文档当时的快照与地址记进新的 `sources`，命令靠它送回对的地方。切掉的条数相加、任一份读残即整张残、歧义度按条数加权、**读进来的框架不再算「洞」**（按域名逐个核销，宁可多报一个洞也不少报）。

### 预算：切出来，不是加上去

`splitBudget()`：每个框架最多 60 条、所有框架合起来不超过一半，顶层拿剩下的。**先枚举框架再读顶层**——切法算不出来就只能事后补，而事后补要把最大的那份文档读两遍。

### 路由

`frameOf(ref)` 是 `makeRef` 的反函数；`routeFor()` 给出 `{frameId, snapshotId, view}`。**顶层那一条刻意保持原样**：它的 `view` 仍然取自 `table.url`——那是线程所说的「这一步属于哪一页」，也正是那道拒绝要比对的值；改成从 `sources` 取会悄悄把一道本该很窄的闸放宽（这一点是被 e2e 的一条既有用例当场抓出来的）。框架才用自己的地址与快照。

`explain` / `ask` 的依据可能跨框架，所以**按框架分组各发一条**，每个文档的浮层画自己那一份——少画一个依据，就又回到「表里没有被读成页面上没有」。

### 顺带修掉的两处

1. **`CLEAR` 改成广播**（`sendToEveryFrame`）。画在框架里的框，只发给顶层是撤不掉的。
2. **宿主所有的抽取收口到 `extractNow`**：`startGuide` 开局那次、`outlineByHand`、`PANEL_EXTRACT` 原先都绕过它。一趟引导的第一张表要是没有框架而之后每张都有，两张一比就成了「这一页的控件变了」——模型会被告知页面变了，而页面什么都没做。

### 验收
