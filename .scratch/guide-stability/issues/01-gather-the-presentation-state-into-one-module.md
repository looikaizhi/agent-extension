# 01 — 【预改造】把「一次呈现」的状态收进一个模块

**What to build:**

内容脚本里和「把某一步指出来」有关的三样状态——当前高亮、目标丢失监听、限次重试——今天散在模块级变量上,彼此能互相重启:重试用尽把监听置空之后,一次重画就能把整套重新拉起来,没有终止条件。

把这三样收进一个模块,只有一个入口。

**这张票不改任何行为。** 同样的输入产生同样的画面、同样的消息、同样的时序。它存在的唯一理由是让 03 和 05 从「在 651 行里动手术」变成小改动——先把改动变容易,再做那个容易的改动。

**Blocked by:** None — can start immediately

**进展记录**

- **新模块 `Presenter`**,放在 `core/overlay/`。持有当前那一步、高亮跟踪、`STEP_CONFIRMED` 的激活监听、settling 宽限、限次重试;代码与注释原样搬入。对外只有 `show` / `retry` / `skip` / `teardown`,加两个只读的 `current`、`target`。
- **为什么是 `core/overlay/`,不是 `entrypoints/` 下的新文件**:三条页面侧守卫(安全上下文 API、扩展存储、改用户选区)按路径划范围,覆盖的只有 `core/extractor`、`core/overlay` 与内容脚本本身。三条**都**覆盖到的只有 `core/overlay`;放在别处,新模块会悄悄跑出守卫的扫描范围。
- **端口**:浮层实例、抽取与敏感字段集合同时被检视模式和 `EXTRACT` 使用,留在内容脚本,以端口借给 `Presenter`;发消息也走端口——`core/` 下的代码不直接碰扩展运行时。
- **`focus()` 留在内容脚本**:守卫断言它恰好只出现在内容脚本那一处。「跳到目标」经 `presenter.target` 取元素。
- **结构监听没有搬**:它按「一趟」计,跨越同一趟里的每一步,不属于某一次呈现;它和 `pagehide` 都经 `presenter.current` 读当前那一步。
- **唯一调整了先后的地方**:teardown 里几个同步步骤的顺序,以及 `HIGHLIGHT` 里「启动结构监听」与「采纳新命令」的先后。已核实不可观察——`TargetTracker` 的 `attach` / `detach` 与浮层的 `hide` 都不会同步回调,回调只在 rAF 与 MutationObserver 里发生。
- 两处测试**注释**(不是断言)里写的「`content.ts` 的 ADVANCING_ACTIONS」改指 `presenter.ts`。
- **验证**:类型检查 0;单测 43 个文件 1808 条全绿(与改动前同数);e2e 191/191(与改动前基线一致)。
- **探针**:往 `presenter.ts` 注入 `crypto.randomUUID()` → 页面侧守卫点名 `src/core/overlay/presenter.ts` 变红;还原后哈希一致,架构守卫 47/47 回绿。
