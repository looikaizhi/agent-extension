# 07c — `wait_for`:等一个说得出口的信号

**What to build:**

模型觉得页面还在加载时,可以说清楚在等什么、最多等多久,等完再决定。

`wait_for` 独立成工具,不并进 `observe`:三家同类产品一致这么分,理由是「等」必须由模型说出等什么、等多久;并进 `observe` 就又变回产品替模型猜。

**动手前定下的三件事**(2026-09-18 用户定,依据是同类产品的一手资料:Playwright MCP 的 `browser_wait_for` 是 text / textGone / time、上限 30 秒,chrome-devtools-mcp 是 `waitForTextOnPage(text, timeout)`,OpenAI CUA 只按时长等):

- **信号词表:文字出现 / 文字消失**,加上最多等几秒。按页面上看得见的文字判定。「只等一段时间」不要——说不出等什么,就又回到猜要等多久。按元素表匹配控件也不要——每次页面变化都得重算可访问名称,大页面上开销大。
- **执行者:内容脚本**,新增一个只读的 `WAIT_FOR` 动词:盯着页面变化,条件一满足就回,到时回「没等到」;宿主随后读一次页面,一并交回模型。不用宿主轮询——轮询间隔又是一个计时常数,变化也可能落在两次之间被错过。这个动词要在「指令集封闭」的守卫里显式加上,它只读、不是执行类。
- **上限:10 秒**。明显小于 service worker 30 秒的空闲回收线,也小于真机每跳约 45 秒的等待;不够就再等一次。模型说的秒数超过上限按上限等,结果里如实说等了几秒。

**进展记录**

- **做了什么**:
  - `wait_for` 经登记处就位:模型说出 `until`(appears / gone)、`text`、`seconds`。秒数在派出等待时封顶到 1–10 秒;说不出等哪段文字(空文字)→ 拒绝。
  - 内容脚本新增只读动词 `WAIT_FOR`(`core/wait/wait-for-text.ts`):一开始就成立就立刻回;否则盯着页面变化,一帧最多读一次可见文字,成立就回;到时再看最后一眼(后台标签页不跑动画帧,变化来了那一帧却不来,不能因此报成没等到)。文字比对前把空白统一成一个空格。页面访问全部走端口,策略在 node 里用假页面、假时钟钉死;真页面只在 e2e 里证明接线。
  - 宿主:等完之后读一次此刻的页面,连同结果交回。等的中途页面跳走了(内容脚本随旧文档一起没了),报「没能等完」——既不是等到,也不是没等到——读的是新页面。
  - 交回模型的话:「等到了:1.2 秒后页面上出现了「X」」「等了 10 秒,没等到「X」出现」「没能等完:等的时候这一页离开了,或者刷新了」,后面附上此刻的页面(不可信内容标签包着)。
  - 07b 的 `observed` 输入泛化成 `tool_result`,带上各自的结果:`observe` 是读到的页面或读不到,`wait_for` 是等待的结局加此刻的页面。结果带回了一张变过的页面,就照页面变化记下(`recordMove`);**等待本身的结局不写进任何地方,只交给模型**。
- **先红后绿**:新测试 `wait-for.spec.ts` 15 条,实现前模块都不存在;另补一条「那一帧一直没来,到时再看最后一眼」——注释里写了这个行为,最初却没有测试钉住。
- **模型输入快照**:带工具轮次的用例加了一轮「等了没等到」;其余差异只有多了 `wait_for` 这个工具和它那一行门槛。
- **验证**:类型检查 0;单测 47 个文件 1879 条,除 2 条漂移检测外全绿;e2e 213/213(新增 3 项:1 秒后出现的按钮被等到并交回、模型指向它画上了屏、等一段不会出现的字 1 秒后如实交回「等了 1 秒,没等到」)。
- **中途修正**:e2e 新场景让浮层滚到了页面底部新加的按钮上,收尾只删了按钮没滚回来,导致后面两个按位置断言的老场景变红;收尾补上滚回顶部。
- **探针**:秒数不封顶 → 只有「封顶在 10」红;每次变化都读页面文字 → 只有「一帧只读一次」红;到时不看最后一眼 → 只有新补的那一条红;等不到时不说等了几秒 → 两条措辞测试加冻结那句话的快照红。
- **没有测到的**:等的中途页面跳走(`met: null`)只有交回模型那句话有单测,宿主那一段没有 e2e——在固定夹具上让页面恰好在等待中跳走,要么靠固定延时(不稳),要么要加专门的夹具,本票没有做。
