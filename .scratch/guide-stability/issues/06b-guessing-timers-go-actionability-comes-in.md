# 06b — 删掉猜测性计时常数,可操作性检查就位

**What to build:**

产品里不再有「猜页面稳定了没有」的计时常数。找不到目标、目标此刻点不了,都是当场交给模型的事实;要不要等,由模型用 `wait_for` 说。

> **2026-09-19 从 06 拆出。** 06 原来还装着 06a 留下的「派出调用时一个侧栏都没开」,那件事与计时常数互不相干,拆到 06c。

**Blocked by:** 05b、05c、05d(已完成)

**Status:** done — 2026-09-19

**拆票时定下的两件事**(用户定):

- **画的时候目标不在页面上**:当场发一条「没找到」读数交给模型,不再有七档重试;同时页面每变一次、主线程空下来时再找一次,找到就画上。没有任何计时。一次呈现只报一次。
- **目标画上了但此刻点不了**:按 Playwright 的定义(可见、启用、命中测试、连续两帧同一 bounding box)在画上之后判一次,不重试;点不了就发一条带原因的读数交给模型。滚动改成瞬时完成,免得产品自己的滚动被判成「还在动」。

**动手前定下的做法**(不改变行为之外的取舍,记在这里备查):

- settling 宽限(5 秒)删掉:「这一步完成了,正在看新页面…」一直留到宿主画下一步或结束,屏上本来就有「结束引导」。
- 结构变化的防抖(400ms)改成「页面变了之后,主线程空下来时看一眼」(`requestIdleCallback`),没有毫秒数。
- 宿主起引导时读页失败的退避重试(400/800/1200ms)删掉,读不到就如实说。
- 保留:`wait_for` 的上限(模型的等待)、模型调用 / 文档抓取 / provider 的传输超时(宿主的等待)、抽取的算力预算、跟踪器的帧计数(机制层)。

- [x] settling 宽限、七档重试、结构变化防抖、滚动上限、宿主读页退避在树上不存在
- [x] 找不到目标:当场一条读数,之后按页面变化接着找,找到就画上;一次呈现只报一次。有测试
- [x] 可操作性的**策略**(几帧算稳、看哪几项、点不了产生什么读数)在 node 单测里钉死,DOM 读取与动画帧走 `Presenter` 的 DOM 端口
- [x] 可操作性的**真实读取**在 e2e 里证明接线(禁用、被遮挡至少各一条)
- [x] 念给模型的两条读数文字更新,`CONTEXT.md` 的 `Reading` / `Actionability` / `Presentation` 跟上
- [x] 类型检查 0,单测、e2e 全绿

**进度记录**(2026-09-19):

- **呈现器**(`core/overlay/presenter.ts`)里不再有任何计时器:
  - 七档重试删掉。画出「找不到」的那一刻报 `TARGET_NOT_FOUND`(不再带次数),之后页面每变一次,等主线程空下来(`requestIdleCallback`)再找一次,多次变化并成一次;找到就画上、报 `TARGET_FOUND`。一次呈现只报一次,同一次呈现重画、按「重试定位」都不再报。
  - settling 宽限删掉:用过的目标消失后画「正在看新页面」,一直留到宿主画下一步或结束,不再到点改画「找不到」、也不再补报一条目标消失。
  - 滚动改成瞬时完成(`behavior: 'instant'`),画一步不再等滚动,`render` 整个变成同步——「等滚动时被新命令取代」这一整类竞态随之消失。回执里没人读的 `scrolled`、只为那一轮存在的 `searching` 一并删掉。
- **可操作性**(新文件 `core/overlay/actionability.ts`,纯逻辑):按 Playwright 的定义,连续两个动画帧读一次(可见、启用、命中测试、bounding box),判一次,不重试。点不了发 `STEP_NOT_ACTIONABLE`(禁用 / 被挡住 / 还在动),宿主作为读数 `not_actionable` 交给模型;看不见不在这里报(那是目标消失,跟踪器报)。只判要用户操作的步(`guide` 固定计划、`locate` 模型的一步),回答的依据不判。DOM 端口加了 `probe` / `nextFrame` / `whenIdle`,单测自己转动帧和空闲。
- **内容脚本**:结构变化的 400ms 防抖改成 `requestIdleCallback`——页面一直在变也总有空下来的时候,而一个不断重启的静默期可能永远等不到。
- **宿主**:起引导读页失败不再退避重试,读一次,读不到就如实说;为那个重试函数存在的 `PageAccess` 端口一并删掉。
- **模型听到的**:「没找到」改成「扩展要画的时候在页面上没找到它的目标。页面之后再变,扩展会接着找,找到了就框出来」;新增「目标在页面上,但此刻点不了:它是禁用的 / 它被别的内容挡住了 / 它还在动」。固定计划收到这两条原地不动(屏上的「找不到」连同重试、跳过就是答案;点不了用户自己看得见)。
- **动手时发现并修掉的两个洞**:
  - 模型指的一步走的是 `locate` 模式(只有多步的固定计划才是 `guide`),可操作性检查起初只在 `guide` 下跑,模型的步子根本不会被检查——单测命令恰好都用 `guide`。补了 A9。
  - 「这次呈现已经报过」的记忆在清屏(`teardown`)时没清。呈现身份是「线程#这一趟的步数」,同一标签页上的下一趟,第一步又是 `#1`,于是被当成已经报过,读数被吞。每一趟结束都会清屏,所以在清屏时清掉。补了 N8、A10。
- **测试**:`presenter.spec` 重写,删掉钉七档重试、宽限、等滚动的 13 条、改写 1 条(T1),新增「找不到」N1–N8、可操作性 A1–A10;每条结束都断言没有留下任何计时器。`readings.spec` 把 `not_actionable` 加进三处表驱动(唤醒、固定计划原地不动、按呈现核对)。e2e:settling 那条改成「没人接手就一直留着,不靠计时改画」;05a/05d 那段按新规则改写(画出「找不到」同时就交给模型;模型挂着不答时,目标回来渲染器自己接上);新增一段证可操作性的真实读取(禁用、被挡住各一条)。
- 探针:拿掉写链对 `not_actionable` 的呈现核对、固定计划对它的原地不动、呈现器的可操作性检查、「页面变了接着找」,各自只红对应测试;均已还原。
- 验证:类型检查 0;单测 1900 全绿;e2e 220/220,连跑 5 轮(1 轮单跑 + 4 轮稳定性)全绿。
