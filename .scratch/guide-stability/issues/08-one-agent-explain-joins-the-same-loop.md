# 08 — 删掉独立的问答 `Agent`,`explain` 并进同一个循环

**Status:** done — 2026-09-19(两张都已完成)

- **08a** — `explain` 在同一个循环里登记,加上行为判据;旧的「问这个页面」照常可用 — done 2026-09-19
- **08b** — 两个输入框合成一个,问答改走同一个循环;删掉问答 agent、它的运行循环与修复轮 — done 2026-09-19

**拆分时定下的三件事**(用户定):

- **合成一个输入框。** 用户只说一句话,模型按行为决定:指出一步就是引导,给出 `explain` 就是问答。这是「不在入口提前分流」的字面意思。
- **引导中给出 `explain`,引导继续。** 回答显示出来,屏上那一步留着,线程照常等下一条读数;`explain` 不推进状态,也不结束这一趟。
- **一次 `point` 都没有、以 `ask` 或 `done` 收场的一趟也算问答。** 照行为判据字面执行:没有 `point` 就不留线程、不写 Run record。
- **(08b 开工时定)引导进行中说的话交给正在走的那一趟。** 它成为一条读数 `said`;没有一趟在走,才开新的一趟。

**原票内容:**

用户只是问「这一页是什么」的时候,不会平白开始一趟引导;而产品里只剩一个 `Agent`。

两个 agent 的实质差别今天只有:问答无状态、不用 tool calling、一次主调用加至多一次修复。走 tool-based 之后,「解释这一页」只是一个不推进状态的 `Output`,不需要第二个 agent 来承载(理由见 `CONTEXT.md` 的 `Agent` 注记)。

问答与引导的分野改成**行为判据**:一趟里一次 `point` 都没有,就是一次 `Question`——不建 `Thread`、不吃步数预算、不写 `Run record`。不在入口提前分流,所以「先看一眼再解释」同样算问答。

**Blocked by:** 07a — 一次一步;07b — 工具循环骨架

> **2026-09-17 拆 07 时挪来:`explain` 在本票登记。** 它在一趟引导里怎么收场——不建线程、不写记录——正是本票的行为判据要定的。循环由归约器驱动(07 拆分时用户定),所以一趟问答跑循环时也需要一份临时记录,结束即删、不写 Run record。
