# 05c — 画之前比对 `View`;generation 只管新鲜度

**What to build:**

高亮框不会画到另一张视图上(症状 2)。

**Blocked by:** 05b — 读数与唤醒

**Status:** done — 2026-09-18

- [x] **(自 02 挪来)** 高亮命令带上它所属的 `View`;画一步之前比对,不一致即拒绝,**绝不按描述符重绑**。这次拒绝产生一条读数,**不**经 `bind_result` 盖 `invalidated`,也不对用户说「未能定位」
- [x] **(自 02 挪来)** 快照 generation 只回答「这份快照还新不新鲜」,画一步的快速路径不再拿它当页面身份
- [x] **(自 02 挪来)** 症状 2 一条测试,本票之前红、之后绿
- [x] 类型检查 0,单测、e2e 全绿

**进度记录**(2026-09-18):

- 高亮命令多了 `view`(出自那张表的地址);呈现层画之前先用 `sameView` 比此刻地址,不一致返回 `view_moved`:不画、不重绑、不启动搜寻;搜寻途中页面换了视图,这一轮就地停下,不报 `TARGET_NOT_FOUND`。快照 generation 的守卫原样留着,只剩「句柄还新不新鲜」这一个意思。
- 宿主收到 `view_moved`,不走 `bind_result`,改为一条读数 `not_shown`(「你指的那一步没有画出来」):重新读一次页面,唤醒模型;固定计划则在新读到的页面上重画。
- 测试:presenter 三条(症状 2 本身、只差 fragment 照画、搜寻途中换视图就停),改动前 V1、V3 红;读数两条(`not_shown` 只唤醒 / 固定计划重画、唤醒消息的措辞)。e2e 新增两段:同文档 pushState 后拿上一页的命令去画被拒;线程里的表属于别的地址时,回答落地后画被拒、变成读数唤醒模型、模型再指一次画上,且不对用户说「找不到」。
- 探针:拿掉画前比对 → V1、V3 红;拿掉搜寻途中的停止 → 只有 V3 红。
- 验证:类型检查 0;单测 1898 全绿;e2e 219/219,连续 5 轮稳定。
- **顺带复现了 05d 那条「未复现」**:上一段的一步还在滚动(最长 800ms)时被 CLEAR 取代,回执 `ref_not_found` 晚到,宿主把 `bind_result` 写到这个标签页此刻的线程上——对用户说「找不到」,还给一步毫不相干的新步骤盖了 `unavailable`。e2e 的 05c 宿主段开头等 1 秒就是在躲它,05d 修好后去掉。
- **pushState 也会触发整页加载完成**:同文档切换在真机上也会送来 `tabs.onUpdated` 的 complete,所以「作答期间同文档换了地址」多半先被 `loaded` 读数作废,走不到画前比对;画前比对兜的是读数还在路上、回答已经落地的那一小段。
