# 06c — 派出调用时一个侧栏都没开

**What to build:**

宿主派出的模型调用总有人执行;真没人执行时,有人告诉用户。

> **2026-09-19 从 06 拆出**(06a 留下的那一条)。

**Blocked by:** None

**Status:** done — 2026-09-19

派出调用时一个侧栏都没开,就没人执行。重新打开侧栏,截止时间之前会显示「仍在进行中」,其实没有人在跑;截止时间过了,也要等下一条消息才清扫。这是宿主发起的等待没有主人。真机 harness 一直开着侧栏,t11/t09 里没有出现过。

**动手前定下的做法**(2026-09-19,用户定两处,标「用户定」):

- 认领者记进调用记录(认领消息自带 `documentId`),不再只记在 service worker 的内存里。一次调用「有人在跑」当且仅当它的认领者还开着——用 `chrome.runtime.getContexts` 问,不猜。
- 派出时一个侧栏都没开:这次调用记成没人跑,不计截止时间;告诉用户。
- **(用户定)侧栏在调用途中被关掉**:下一次有动静时发现——用户点了、页面变了、侧栏打开时,查认领者还在不在。没有端口,没有计时。
- 任何侧栏一打开:没人跑的调用(从没被认领的、认领者已经关掉的)原样重新派出,截止时间从头算。
- **(用户定)告诉用户**:浮层卡片上写一句「打开侧栏,引导才能继续」,扩展图标加角标(点图标就打开侧栏)。侧栏一开、调用重新派出,两者都撤掉;这一趟结束也撤掉。
- 截止时间只管有人认领、认领者也还开着的调用。

- [x] 侧栏晚于派出打开:调用照样执行,不会被当成超时。有测试
- [x] 侧栏在调用途中关掉:下一次有动静时发现;有别的侧栏就改派,没有就告诉用户。有测试
- [x] 没有侧栏能跑时,浮层上有那句话、图标上有角标;侧栏一开就撤掉。e2e 证明
- [x] 类型检查 0,单测、e2e 全绿

**进度记录**(2026-09-19):

- **认领记在调用上**。`EFFECT_CLAIM` 带上线程,宿主在每线程的写链里裁决(`judgeClaim`):第一个来的拿到;认领者还开着,别人(包括它自己再问)一律拒绝;认领者已经关了,下一个来的接手。认领者是发消息的那个侧栏文档(`sender.documentId`),写进调用记录后才回话。service worker 内存里那个认领集合连同它「被回收了也无妨」的长注释一起删掉——被回收之后,它确实会让第二个侧栏跑同一次调用。
- **「有人在跑」问浏览器**:`chrome.runtime.getContexts` 问此刻有没有侧栏开着(按 `sidepanel.html` 的地址,侧栏和在标签页里打开的同一页都算)、认领者那个文档还在不在。
- **派出**:有侧栏开着就广播;一个都没有,这次调用照旧在途、没人认领,浮层卡片上写「引导在等侧栏……点工具栏上的「页面引导」图标打开侧栏」,图标加红色角标「!」、提示文字换成同样的话。
- **交回再派**(`unrunGuideEffect`):没人认领、或认领者已经关掉的调用,清掉认领、截止时间从头算,原样再派一次。两个时机:侧栏挂载时(`PANEL_GUIDE_INFLIGHT`,对所有标签页的线程——侧栏执行每个标签页的调用),和页面上有动静时(读数到达、线程还有在途调用、这一次没有新派出)。重复派出无害:认领按调用裁决,只会被认领一次。
- **截止时间**只管有人认领的调用(`judgeRecovery`):没人认领的还没开始,谈不上迟到。于是「侧栏晚开、调用被当成超时」这条路没了。
- **撤掉**:调用派给了开着的侧栏,或这一趟结束时,角标、提示文字、浮层那一行都撤掉。
- 内容脚本多了一个动词 `WAITING_FOR_PANEL`(只往我们自己的浮层卡片上写一行、或撤掉),架构守卫的动词清单随之改,注释写明理由。
- **测试**:新文件 `who-runs.spec.ts` 12 条(认领五条、交回五条、截止时间两条);`effect.spec` 里三条「内存集合先到先得」删掉(被取代),`judgeRecovery` 那条补上「没人认领不算迟到」,两处截止清扫的测试先认领再过期。e2e:06a 那段「结果迟到」的夹具补上认领者;「重新打开侧栏时说出上一次超时」两条删掉——那正是 06c 改掉的行为(没人跑过的调用,侧栏一开就重新派出),而且那段的前提「没有侧栏开着」其实不成立;文件末尾新增一段,真的一个侧栏都不开,证派出时没侧栏、侧栏途中被关两条路。
- **顺手修掉的测试卫生问题**:e2e 1263 行开的 `panel2` 从没关过,之后整个套件里一直有一个多余的侧栏在认领调用(08b 里 Q-5d 读不到 `qaPanel` 的花费,就是它)。
- 探针:「没人认领也按截止时间判超时」「认领者开着也放行」「认领者开着也交回」「交回时截止时间不从头算」,各自只红对应测试;均已还原。
- 验证:类型检查 0;单测 1909 全绿;e2e 227/227,关掉多余侧栏之后连跑 6 轮全绿。之前有一轮(多余侧栏还开着时)05a「目标回来自动接上」红过一次,补上失败细节后没再复现,记在这里备查。
