# 05d — 「找了一轮没找到」改成读数交给模型

**What to build:**

找不到目标,是一件交给模型判断的事实,不是宿主写死的结论。

**Blocked by:** 05b — 读数与唤醒

**Status:** done — 2026-09-18

- [x] **(05a 留下)** 05a 里「这一轮用尽」由宿主盖 `unavailable` 并告诉用户。改成一条「找了 N 次没找到」的读数交给模型
- [x] **(05a 发现,05c 复现)** 一次呈现在画的途中被取代(下一条命令,或 CLEAR),回来的也是 `ref_not_found`(没画上屏);宿主分不清它和真正的拒绝,照样经 `bind_result` 盖章并告诉用户——而且写到的是这个标签页**此刻**的线程上,可能是另一趟引导的另一步。复现方法见 05c 进度记录;e2e 的 05c 宿主段开头那 1 秒等待是在躲它,修好后去掉。读数取代「从回应下结论」之后应随之消失
- [x] 类型检查 0,单测、e2e 全绿

**进度记录**(2026-09-18):

- **找了一整轮没找到 → 读数**:内容脚本的 `TARGET_NOT_FOUND` 带上一共找了几次(第一眼加这一轮每一次,包括被页面变化提前的那几次);宿主把它当成读数 `not_found` 交给模型(「你指的那一步，扩展在页面上找了 N 次都没找到它的目标」),不盖章、不对用户说「找不到」。固定计划没有模型可问:屏上那张「找不到」连同重试、跳过就是答案,什么都不做。
- **宿主不再从画面的回执下结论**:归约器的 `bind_result` 输入删了。回执只转给侧栏显示;其中两种拒绝是这一步本身的事实,变成读数 `not_shown`(`elsewhere`:页面已不在它所属的 View;`sensitive`:目标是密码这类敏感框)。固定计划对 `sensitive` 也不重画——再画一次还是一样,会原地打转。
- **说的是屏上那一步的读数,都按呈现身份核对**:`used`、`not_shown`、`not_found` 对不上此刻那一次呈现就丢掉,页面也不读。「被取代的回执写到下一趟的线程上」随之在结构上不可能:回执不再有进线程的入口。
- **随之删掉的**:`handleBindResult` 与「找不到这一步的目标，页面可能已经变化」这句通知、`applyTargetNotFound`、`CL-2`(只写不读的标记)与早已无人调用的 `judgeFirstStepBind`;`Binding` 挪到 `binding.ts`,只为侧栏服务。
- **`unavailable` 收窄成唯一剩下的来源**:P-3(跨站落地页要凭据)。念给模型的那句改成「引导在这一步之后为安全停下了」,侧栏标签改成「为安全停下」;模型输入快照因此重录,diff 只有这一句(两个快照文件各两处)。
- 测试:读数一侧 8 条新用例(`not_found` / `not_shown` 的唤醒与措辞、固定计划不重画、呈现身份核对),presenter 的「一共找了几次」;删掉测已删机制的 11 条(`bind_result` 三态、盖 `unavailable` 的几条、`applyTargetNotFound`、`judgeFirstStepBind`)。e2e 05a 段第二部分改为「这一轮找完 → 作为读数交给模型、不说找不到、不盖章」;05c 宿主段开头那 1 秒等待删掉。
- 探针:固定计划对 `not_found` / `sensitive` 重画 → 两条红;`not_found` 不核对呈现 → 一条红;不计找的次数 → 一条红。均已恢复。
- 验证:类型检查 0;单测 1894 全绿;e2e 220/220,去掉 1 秒等待后连续 5 轮稳定(之前约三成被迟到回执打坏)。
- **没做**:`HighlightFailure` 里的 `not_visible`、`frame_unreachable` 在源码里没有产生者,留着没动;对上多个候选(`ambiguous`)现在只画出来、不告诉模型——旧日的 `CL-2` 也从没告诉过它。
