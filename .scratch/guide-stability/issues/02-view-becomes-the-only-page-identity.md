# 02 — `View` 成为唯一的页面身份

**What to build:**

用户点进新的一页之后,引导说的话和画的框都属于他**现在**这一页。

今天有五个互不兼容的「这是哪一页」,它们在两个方向上各错一次:站内搜索换了关键词而按钮长得一样时,产品认为用户没动过,于是拒绝提交新的元素表;而快照序号被当成页面身份时,一份正确的计划会被画到另一张视图上。

统一成一个 `View` = **完整 URL 去掉 fragment**,不掺任何结构(理由见 `CONTEXT.md` 的 `View` 词条)。结构指纹保留,但职责改成只回答「这一页上东西变没变」,永不回答「这是哪一页」。

**Blocked by:** None — can start immediately(可与 01 并行)

**Status:** done

**进展记录**

- **做了什么**:
  - 新模块 `shared/view.ts`,只有 `sameView` 与 `redactUrl` 两个导出,零 import。`redactUrl` 从抽取模块原样搬来——`View` 必须两边都先脱敏再比,而归约器的纯度守卫不许它的依赖闭包里出现 DOM 代码。
  - 结构指纹不再掺 origin+pathname;字段 `pageHash` 全仓改名 `structureHash`。
  - `pageMoved`(布尔)换成 `pageChange`,返回 `moved` / `changed_in_place` / `none`:先问 `View`,再问结构与控件。
  - `samePlace` 的五个调用点全部换成 `sameView`:落点、打转兜底、Fixed plan 的「用过」、新出现控件的标记、重规划闸门。`place.ts` 删除。
  - 结果回来时的世界比对,以及「网址没变的 `done` 照收」那条例外,都改按 `View` 比。
  - 架构守卫里写死 `place.ts` 的那条改指 `shared/view.ts`。
- **补上的一处回退**:结构监听器以前能察觉同文档切到另一个路径,**唯一的原因是路径被一起算进了哈希**。拿掉之后,它改为同时记下上次上报时的地址,结构变了或 `View` 变了都上报。覆盖面不比以前少,还补上了以前漏掉的「只改查询参数」。
- **为什么症状 1 不在这里**:逐条查了 t11 原始轨迹。在「要离开的页」上发出的调用共 10 次,其中 **8 次表地址与上一次调用相同**——用户点了之后、离开之前,旧页面自己加载完了(控件 161–168 → 339–340);只有 2 次是地址先变、DOM 没跟上。前 8 次地址根本没变,任何比地址的办法都查不出。本票做完的是后 2 次的前提:「这是哪一页」与「内容变没变」终于分开了。
- **为什么症状 2 与「画之前比对」不在这里**:在触发器驱动的架构里,「拒绝画」没有诚实的去处——画一步失败会经 `bind_result` 盖 `invalidated` 并说「未能定位」;拒绝之后什么都不做会静默卡死;拒绝之后主动重规划可能无限循环。只有读数出现之后才有去处,所以放到 05。
- **有意的语义变化**:**只改查询参数现在算换页**。影响落点、打转兜底、Fixed plan 前进、新控件标记、重规划闸门、结构监听。随之带来的风险:SPA 若先改地址、后渲染,会提交旧 DOM。这和改路径时的情况是同一个问题,已写进 05。
