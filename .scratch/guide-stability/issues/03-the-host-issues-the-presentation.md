# 03 — `Presentation` 由宿主签发,内容脚本不得自行续命

**What to build:**

目标短暂消失又回来的时候,引导不再自说自话地重启一套监听,也不再没有终止条件地重试下去。

宿主签发「这一次把某一步指出来」的身份,内容脚本的高亮、丢失监听、限次重试全部挂在它下面。宿主换一次呈现,旧的那一份连同它的全部计时器立即作废。

这修的是症状 3 的**前一半**——内容脚本这一侧。宿主抢先写死「未能定位」那条路径在 05 里删。

**Blocked by:** 01 — 把「一次呈现」的状态收进一个模块

**Status:** done

> **2026-09-17 实施时,用户定了两条验收的去留**(依据见进展记录):「重试用尽要有回调」挪到 05;「重画不能把用尽的重试重新拉起来」不保留,改为相反的规定。

- [x] 类型检查 0,现有单测与 e2e 全绿

**进展记录**

- **为什么两条验收变了**:
  - 「用尽要有回调」:宿主现在收到这个消息没有诚实的处理方式——盖章是写假事实,触发重规划可能循环,什么都不做就是死代码。和 02 里「拒绝画」是同一个坑,只有 05 的读数能接住它。
  - 「重画不重启」:每次重画都是宿主在响应**页面变化**,页面变了再找一轮,正是症状 3「马上要回来的目标别放弃」要的。所谓「没有终止条件」其实不存在——每一轮都有上限,重启只来自宿主的重画。禁止重启反而会让 Fixed plan 在菜单展开后只试一次。这两条是按代码推演定的,没有真机数据。
- **先做了预改造(行为不变)**:`Presenter` 用到的页面操作收进 `core/overlay/dom.ts`,以端口注入——解析 ref、滚动、跟踪元素、监听点击、监听 DOM 变化、取矩形。`Presenter` 于是只剩类型 import,能在 node 里配假计时器跑。验证:类型检查 0;单测 1817;e2e 191/191。05、06 要改的策略都在这个模块里,这一步也让它们能在 node 里测。
- **呈现身份**:协议加 `HighlightCommand.presentationId`,宿主在三处签发:
  - 画步骤:`线程#历史条数`。每换一步宿主都会追加一条历史,重画不追加,所以同一步重画保持同一个身份,不需要任何新状态;
  - 澄清时框出候选:`线程#clarify-历史条数`;
  - 问答:每次随机。
  线程结束时宿主一定发 `CLEAR`,两趟引导之间不会串用呈现。
- **修掉的泄漏**(每条都先确认红、红的理由对,再实现):
  - T1:旧的 settling 计时器在新呈现被画成「找不到」之后,以新那一步的 ref 报 `TARGET_LOST`;
  - T2:新呈现沿用旧呈现剩下的重试次数——「已经在找」只看有没有一轮在跑,不看是为谁在找;
  - T6:新呈现被画成「找不到」之后,点旧目标报上去的是新那一步的 `STEP_CONFIRMED`,一步没做的事被记成做成了;
  - T7:同样情形下,旧跟踪器以新那一步的名义报 `TARGET_LOST`;
  - T8:新呈现等滚动(最长约 800 ms)期间,旧 settling 计时器到点,以新那一步的名义说话;
  - T9:被新命令取代的那次 `show` 醒来之后,把新呈现正在进行的查找停掉。这是旧代码里就有的竞态。
- **机制只有一个**:一次渲染决定上屏的那一刻——所有拒绝都已返回、还没等待任何东西——同步结束所有不属于它的跟踪器、监听、计时器和重试。被拒绝、没上屏的新呈现不结束旧的,守住「拒绝不留痕迹」。中途一度在每个回调里各加一道归属核对,探针证明它和「上屏时结束」重复,而后者没有测试钉住,已收成一个。
- **守卫性测试(本来就绿)**:T3 同一次呈现被重画、重试还在跑 → 沿用剩余次数;T4 重试用尽后重画 → 再找一轮(用户定);T5 「重试」按钮不会开始一次新的呈现。
- **探针**:去掉上屏时的结束 → T1/T2/T6/T7/T8 红;去掉被取代时的直接返回 → T9 红;去掉「已经在找就不重启」→ T3 红。每次都还原并核对哈希一致。
- **验证**:类型检查 0;单测 44 个文件 1826 条全绿(新增 `presenter.spec` 9 条);e2e 191/191。
- **没有真机证据**:重规划轨迹只写在 `chrome.storage.session`,harness 打印到控制台后就没了,没有落盘。这几处泄漏在真机上发生过多少次,拿不出数字,修法和测试都只依据代码。以后要量化,harness 得先把重规划轨迹写进日志。
- e2e 里有些高亮命令是测试直接发的,不带 `presentationId`。那条路径上所有身份都是 `undefined`,被当作同一次呈现,行为和改动前完全相同。
