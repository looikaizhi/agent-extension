# 04 — 一步的结果拆成 `action` × `effect`

**What to build:**

用户照做了、页面也确实变了的时候,引导不再说「这个控件推不动,换一个入口」;在同一页上展开一个菜单、打开一个下拉这种**不换地址**的一步,同样算数。

今天「用户点了」和「页面变了」被焊在一个值里,而唯一记录效果的字段只在跨页时才写——原地生效必然留空,于是打转兜底把它读成「这一步没推动任何人」。等待超时盖的又是同一个值,而那个值对用户的说法是「这个控件推不动」。

拆成两个正交字段:`action`(`taken` / `skipped` / `unavailable`)与 `effect`(`moved` / `changed_in_place` / `none` / `unknown`)。

> **这是最重的一张。** 约 6 个源文件、13 个测试文件、8 个 eval 代码文件。全部是机械改动。
>
> **更正(2026-09-17)**:这里原先写「冻结语料不含这些字段」,**是错的**。当时筛文件用的是 `\.json$`,而语料的扩展名是 `.ndjson`,一个都没筛进来。用系统 grep 核实:`batch-1.ndjson` 里 `landedAt` 160 次、`"confirmed"` 258 次;`on-target.ndjson` 分别是 55 次、74 次。
>
> 结论仍是**不迁移**,但理由不同:**没有任何单测读这两份语料**,只有决策评估的命令行脚本(`run.mjs`、`batch.mjs`、`on-target.mjs`、`pull-annotations.mjs`)读;而且 grilling 已经定了,旧语料留作历史、不再当闸门。所以不加兼容层,也不改写数据。本票之后再拿它们回放,喂给模型的历史是旧形状,结果没有意义——这本身就是「不可比」的一部分。

**进展记录**

- **真机数据先行**:
  - t11 各趟最后一次调用的历史里,`confirmed` 131、`failed` 9、停在未定的 5。
  - **9 条 `failed` 全是「点了、起了作用、只是这一页没变」**,前后两张表地址相同、控件完全一样:复制克隆地址 2 次,gitee README 里在新标签页打开的链接 4 次,阿里云「ECS 控制台-实例」2 次。可念给模型的都是「推不动,换一个入口」。
  - 停在未定的 5 条,全是超时后计划直接前进、没盖章的路径(07 删)。
- **更正 1:落点不能直接删。** `landedAt` 记的是去向,会念给模型——「之后到了 X」。规格说它「被 `effect` 取代」,漏掉了这一点。现在 `effect` 是 `{ kind: 'moved', to }` / `{ kind: 'changed_in_place' }` / `{ kind: 'none' }`,「换了页却没有去向」这种状态根本写不出来。
- **更正 2:等待超时是 `none`,不是 `unknown`。** 重规划只有在确实读到页面、而且每一次都判「没变」之后,才会上报超时;一次都没读到时走 `unreadable`,根本不会上报。`CONTEXT.md` 里对应的说法已经一并改正。
- **补记规则**:一步定了结果之后,唯一还能补的是去向,而且只补给还没有去向、或者只是原地变化的一步。已判「没变」的不改写。5 轮真机里「先没变、后换页」出现 0 次;「先找不到、后换页」在 t09 出现过 2 次,照旧补上去向。
- **`taken` 是推断,不是观察**:模型规划下归约器并不知道用户点了没有(`step_used` 只有 Fixed plan 在用),只知道「某一步在屏上时页面变了」。这和旧 `confirmed` 原有的推断完全一样,注释里写明了;要拿到点击的证据,得等 05 的读数。
- **唯一有意的行为变化**:Fixed plan 按「跳过」现在记为 `skipped`(以前留在未定)。不算确认;也不进模型输入——Fixed plan 从不调模型。
- **侧栏**:以前「超时没变化」的一步,直接把原始值 `failed` 显示给用户(`OUTCOME_LABEL` 里没有这一项)。现在显示「点了,这一页没有变化」;另外补上了「跳过」。
- **删掉一条测试**:B-3「落点缺失 → 按老规矩拦」。它测的是一条没有任何落点记录的旧条目,这种状态在新模型里不存在,转换之后与 B-2 一模一样。
- **逐字节不变的证据**:模型输入快照测试的夹具改成新形状之后,对着**原封不动**的快照文件跑绿;三份快照的哈希与改动前一致。
