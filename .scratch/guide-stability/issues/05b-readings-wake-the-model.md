# 05b — 读数与唤醒:环境只写读数,读数唤醒模型

**What to build:**

环境不再有权推进引导的状态。

四个观察源——整页导航完成、用户用了我们指的那个目标、目标消失、页面结构自己变了——今天各自等一个窗口、页面变了就当场「提交」:记下这一步做成了什么、换上新表、调模型;为了不互相赛跑,还得套一个 latest-wins 队列。改成:它们**只写一条带出处的读数**(何时、看见了什么、谁看见的);读数唤醒模型,由模型读到之后决定。

**实施时定下的细节**(2026-09-18):

- **读数让进行中的整段对话作废**,不只是在途的调用:工具在执行时来的读数也一样。一段对话只对一个世界成立——`read_doc` 在抓取时页面换了,模型拿着旧表的 ref 回答,核对却用新表,同名 ref 指向别的元素。
- **宿主在写链里读页面**:读数的抽取与落地是同一个串行单元,晚抽完的旧页不会盖掉早抽完的新页;没有引导、或点击报告对不上屏上那次呈现,就不抽取。
- **唤醒消息说三件事**:自上次回答以来的读数(先发生的在前)、此刻这一页和模型上次回答时那一页的比较(地址变没变、控件变没变,或此刻读不到)、以及新出现的控件标记。
- **P-3 挪到 `Output` 落地时**:读数不推进任何状态,安全停止也不例外;跨站之后第一次落地的回答,核对它读到的那一页。
- **点击报告改名 `STEP_USED`**,带上呈现身份和「点了 / 填了」;填值步骤在目标的 `change` 上报一次(输入完才算,不在第一个按键唤醒模型)。可编辑区没有 `change`,这一类仍然证明不了,已知缺口。
- **固定计划的 `effect`**:第 N 步做成了什么,在用户对第 N+1 步动手时判定——从「点完第 N 步那一刻读到的页」到「对第 N+1 步动手前最后读到的页」;最后一步比「点它之前最后读到的页」和「点完那一刻读到的页」。
