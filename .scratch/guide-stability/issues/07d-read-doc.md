# 07d — `read_doc`:抓文档的那半截循环接通

**What to build:**

模型要先读一份站内文档才能决定下一步时,真的能读到。

今天 `need_docs` 只做了前一半:宿主判定这条链接能不能抓,然后告诉用户「扩展还不能替你读取它」。侧栏的抓取执行者其实已经写好了,只是请求从来没发出去,正文也没有送回模型的地方。工具循环(07b)补上了后者。

**Blocked by:** 07b — 工具循环骨架

**Status:** done

- [x] `need_docs` 改名 `read_doc`
- [x] 宿主判定能抓之后,请求真的交给侧栏;正文作为工具结果回到模型,当作不可信内容包起来,有长度上限
- [x] 宿主拒绝抓取、抓取失败,理由都送回模型,由它决定下一步
- [x] 「扩展还不能替你读取它」这条通知在树上不存在
- [x] 类型检查 0,单测、e2e 全绿

**进展记录**

- **做了什么**:
  - `need_docs` 改名 `read_doc`(模块、类型、测试、评测代码、录音脚本、标注文件里的 1 条标注),门槛说明写清了它是干什么的、正文最长多少。
  - 宿主判定能抓 → 请求真的发给侧栏(写入器的 `toEffectRequest` 不再对抓取返回空),线程等着它的结果;抓取结果回到归约器,成为这一轮的结果,带着整段对话再问模型。
  - 宿主不抓(链接有红旗、找不到链接)→ 不再通知用户,理由成为这一轮的结果交回模型,模型接着决定。抓取失败、过期被清扫,同样作为「没读到」交回模型。
  - 抓的时候页面变了 → 这份正文不接上,按新页面重新问一次(E-3,和模型回答在变了的世界里到达时一样)。
  - 正文最多 **8000 个字**(每一轮都要重发,大约三张大元素表),截过就如实告诉模型。截断在宿主做,不信侧栏(§8.3)。正文和页面一样包在不可信内容标签里。
  - 侧栏:网页用浏览器自带的 `DOMParser` 取正文(去掉脚本、样式,优先取页面标明的主体内容);文字类原样;PDF、图片这类按类型拒绝,不把字节交给模型。**跳转不跟**:`redirect: 'manual'` 下连跳到哪都看不到,跳过去的地址也没有经过核对,所以如实说「这条链接会跳到别的地址」,由模型决定(通常是改指那条链接)。
  - 「扩展还不能替你读取它」这条通知,连同为它兜底的「撤掉在途标记」逻辑,在树上不存在了。
- **一个参数**:正文上限 8000 字是我定的(票上只写了「有长度上限」),依据是它在一步之内每一轮都会重发。要调就改 `DOC_TEXT_MAX_CHARS` 一处。
