# 05a — 找不到目标时,等这一轮重试用尽再下结论

**What to build:**

马上就要出现的目标,不再被提前判死。

今天画一步时,如果目标暂时不在页面上,内容脚本会先画出「找不到」、同时启动一轮重试(7 次,约 16 秒),然后把 `ref_not_found` 返回给宿主。宿主**立刻**把这个结果当成 `unbound`:盖上 `unavailable`,并对用户说「未能定位」。等目标真的出现,内容脚本发出 `TARGET_FOUND`,宿主却只更新侧栏——历史已经盖了章(先到先得,改不回来),那句话也收不回来。

改成:**画成「找不到」、而内容脚本还在找**的那一步,宿主先不下结论,等这一轮的结果:

- 这一轮里目标出现了 → 这一步照常,不盖章,也不说「未能定位」;
- 这一轮用尽了 → 内容脚本报一次「找了 N 次没找到」,宿主**这时**才盖 `unavailable` 并告诉用户。

> **更正 03 里的一个判断。** 03 实施时我把「重试用尽要有回调」挪到了 05,理由是宿主收到这个消息「没有诚实的处理方式」。这句话在这里不成立:把**已有的**「未能定位」从「第一次没找到」挪到「整整一轮都没找到」,恰恰就是诚实的处理——那时目标确实在一整轮里都没有出现。当时我把「用尽之后该怎么办」和「读数交给模型」两件事混为一谈了。
