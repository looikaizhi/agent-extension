# 07b — 工具循环骨架,加上 `observe`

**What to build:**

模型在回答之前能再看一眼页面,看完再决定。

**归约器驱动**(用户定):每一轮工具调用都是一次 `Effect`。模型调用 `observe` → 宿主取此刻的页面 → 结果交给归约器 → 归约器带着这一步的工具对话再派一次模型调用。判定权留在宿主:`point` 永远对照宿主亲手取的那张表核对;service worker 被回收之后,也能从持久化状态接着走。

**Blocked by:** 07a — 一次一步

- [x] 每次唤醒(触发器提交新表、E-3 重规划)或一个 `Output` 落地时,工具对话清空;走过的步骤照旧由历史带着

**进展记录**

- **做了什么**:
  - 工具对话(`Turn`,已进 CONTEXT.md)存在线程上:这一步开始时的那一页,加上每一轮「模型的调用 + 送回的结果」。每次唤醒重开;`Output` 落地或调用失败就收起。登记处的每个模块多了一个 `kind: tool | output`,由它决定一次回答之后对话是继续还是收起。
  - `observe`:模型说要再看一眼、并说清为什么;宿主就地读一次这一页(不按时钟重试),读到了就交表,读不到就交「读不到」;归约器记下这一轮,带着整段对话再派一次模型调用。之后的 `point` 对照新读到的那张表核对,schema 里的 ref 枚举也来自它。
  - 读到的是另一页,就按页面变化记下(和触发器提交新表走同一个 `recordMove`)。
  - 模型看到的消息:首条是这一步开始时的那一页(每轮逐字节重建,前缀缓存照样命中),之后每一轮是一对 assistant 调用与 tool 结果,按调用 id 配对;读到的页面同样包在不可信内容标签里、用自己的 nonce。
  - 线上只在对话有了轮次时才带 `turn`,所以没有工具轮次的调用与改动前逐字节相同。
  - 端点不给调用 id 时,归约器用这次调用的 effectId 造一个(`call_<effectId>`),重放时两边一致。e2e 的模型桩就不给 id,这条路径是真机形态走通的。
- **一个设计上的取舍**:`observe` 不占在途调用(`inflight`)的位置,而是记在对话的 `pending` 上、按 id 对上读数。宿主是在同一个处理函数里就地读的;给它也立一块墓碑,service worker 在读的中途被回收时,墓碑会留下来把线程焊死——那正是 06 要消灭的一类。现在读数迟迟不来,只意味着下一次唤醒重开对话,迟到的读数被丢掉。
- **已知的中间态**:
  - 每一轮工具调用都是一次模型调用,在 09 之前照旧计入整趟 12 次配额。模型要是反复 `observe`,会更早用完配额——`observe` 的门槛写明了「表里已经有能往前走的控件时不要为了保险再看一眼」,真正的收敛靠 09 的每步上限。
  - **提示词漂移检测 2 条是红的**(系统提示词、工具 schema 与录音逐字比对):按用户决定,07 系列只在 07d 末尾重录一次真实模型语料。其余单测全绿。
- **先红后绿**:新测试 `tool-loop.spec.ts` 14 条,实现前 13 条红。其中「读到的是另一页」一条最初写得太弱——现有路径在唤醒时早已记下了屏上那一步,改动前它也会过——改成只有读数才能证明的情形(先原地变化、再看一眼时页面已经走了)。
- **模型输入快照**:加了一个带工具轮次的用例(一次读到、一次读不到),冻结轮次的形状;其余差异只有多了 `observe` 这个工具和它那一行门槛。
- **验证**:类型检查 0;单测 46 个文件 1863 条,除上述 2 条漂移检测外全绿;e2e 210/210(新增 3 项:第二次调用带着配好对的这一轮、读回的是包好的此刻元素表、模型用新表的 ref 指的一步画上了屏)。
- **探针**:读数不核对 id → 只有「对不上 id 的读数」红;`Output` 落地不收起对话 → 只有「point 对照刚读到的表」红;唤醒不重开对话 → 只有「读的时候页面变了、另起一次调用」红;宿主不执行 `observe` → 只有新加的 3 项 e2e 红。
